계획은 4일이었고 D1~D3이 하루에 끝났다.

### ② 화면 수 표기
실제 파일은 **화면 8개 + 인쇄 레이아웃 2종 = 10개**.
"9개 화면"으로 세던 초기 기준과 다르다. 발표 자료에서 하나로 통일할 것.
권장 표기: "화면 8개, 인쇄 레이아웃 2종".

## 5. 알려진 한계 (고치지 않기로 한 것)

| 항목 | 이유 |
|---|---|
| 브라우저 뒤로가기로 이탈 시 방문 기록 유실 | App Router에 이동 가로채기 공개 API 없음. `history` 조작은 부작용이 큼 |
| 동시 요청 중복 3건 (등록·질문 토글·항목 추가) | 클라이언트 가드로 막음. 서버 차단은 스키마 변경이 필요해 보류 |
| 도보 최소거리 미지원 | 카카오 길찾기는 유료 API. 직선거리 + "직선거리 기준 추정" 병기가 R8의 표현 |
| 면적·관리비 빈 값이 0으로 저장 | nullable 스키마 변경 대신 표시로 우회. 관리비 0은 실제 값일 수 있어 그대로 표시 |
| 홈·비교 화면 `Ctrl+P` 시 화면 그대로 인쇄 | 인쇄 버튼이 없는 화면. MVP 범위 밖 |
