  - `deal_type`은 PG enum이 아니라 **text**라 `'사글세'` 값 추가에는 DDL이 필요 없었다
  - 적용 후 실측: 기존 13행 모두 두 칸 NULL, `deal_type` 분포 무변(전세 5 · 월세 8). 테이블 재작성 없음
  - **되돌리기**: `ALTER TABLE properties DROP COLUMN prepaid_months;` + `... prepaid_total;` +
    `DELETE FROM drizzle.__drizzle_migrations WHERE id = 2;` (현재 행은 id=1, 2 두 개)
    → 되돌릴 때 잃는 것은 사글세 매물의 선납 정보뿐이다. **쌓이기 전에 되돌리면 손실 0**
- [x] 인덱스 4개 생성 확인: `properties_user_idx` / `properties_status_idx` / `questions_prop_idx` / `visit_checks_prop_idx`
  - (이 문서에 2개로 적혀 있었으나 스키마상 properties 인덱스 2개가 추가로 있음)
- [x] 실 서버 버전 확인: PostgreSQL 18.4 / `drizzle.__drizzle_migrations` 1건 적용
- **무료 한도 (확인일 2026-08-11, 콘솔 대시보드)**
  - Compute 100 CU-hrs/월 · Storage 0.5 GB · Network transfer 5 GB · Branch 10개
  - 최소 0.25 CU 기준 약 400시간 → 4일 데모 규모에선 여유
- 메모: **scale-to-zero 있음.** 일정 시간 무요청 시 컴퓨트 정지 → 재기동 콜드 스타트.
  발표 직전 앱 1회 접속으로 웜업 필요. 웜 상태 응답은 0.26~0.48초.
- **현재 데이터 상태 (2026-08-12 12시 실측): 더 이상 비어 있지 않다.**
  `users 22 · properties 9 · visit_checks 89 · questions 90 · ai_logs 11`.
  세션 생성 시각이 08-11 20시 ~ 08-12 11시에 걸쳐 있고 매물을 만든 세션이 5개다.
  → **팀원들이 이미 배포본을 쓰고 있다는 뜻이다.** (누가 썼는지는 익명 세션이라 알 수 없다)
- ⚠ 그래서 **`DELETE FROM users`를 절대 그냥 돌리지 않는다.** FK CASCADE로 팀원 데이터까지 지운다.
  정리할 때는 세션별 매물 수를 먼저 뽑아 보여준 뒤 범위를 좁힌다:
  `SELECT u.id, count(p.id) FROM users u LEFT JOIN properties p ON p.user_id=u.id GROUP BY u.id;`
  스크린샷 러너(`tests/e2e`)도 같은 이유로 **자기 QA 세션의 행만** 지운다.

## 5. D4 오전 리허설 체크리스트

> 발표 직전에 순서대로 확인한다.

> 2026-08-12 갱신 — 이 목록을 처음 쓴 뒤 `/admin`·홈 랜딩·사글세·스크린샷 러너가 생겼다.

### 접속·데이터

- [ ] **Neon 웜업** — 배포 URL에 1회 접속해 scale-to-zero 콜드 스타트를 미리 털어낸다.
      웜 상태 응답은 0.26~0.48초. 이걸 빼먹으면 첫 화면이 수 초 멈춘다
- [ ] 시연 데이터가 들어가 있는지 — 지도에 핀이 찍히고 **비교 화면이 열리는지(활성 매물 2건 이상)**
      (`npm run qa:demo` — 시연용 40건. 실사용 데이터는 건드리지 않는다)
- [ ] **사글세는 시연 중 직접 등록해서 보여준다.** 시드 40건에 사글세가 없다 —
      없는 데이터를 만들지 않기로 했다. 등록 폼에서 사글세를 골라 선납 개월·총액을 넣는 흐름을
      리허설에서 한 번 돌려볼 것 (팀원이 실사용으로 만든 사글세 1건이 이미 있다)
- [ ] `/admin` 상단의 `실사용 N건 · 시연용 M건`을 미리 읽어둘 것. 발표에서 이 숫자를 말한다.
      **시연용 숫자로 "실제로 쓰였다"고 말하지 않는다** — 실사용 숫자가 더 강하다
- [ ] ⚠️ **"세션 수"를 사용자 수로 말하지 않는다.** 쿠키 없는 요청마다 세션이 발급돼
      봇·크롤러·점검 스크립트가 전부 잡힌다(실측: 세션 177 중 매물을 만든 것은 10).
      발표에서 쓸 숫자는 `/admin` 요약의 **매물 보유 세션**이다

### 시연 중 실제로 입력할 값 — 미리 정해 둔다

- [ ] **등록 시연 주소는 아래 셋 중 하나만 쓴다** (2026-08-12 지오코딩 실측 통과)
  - `경상북도 경산시 진량읍 대구대로 238`
  - `경상북도 경산시 진량읍 진량내리길 30`
  - `경상북도 경산시 진량읍 대구대로58길 3`
  - ⚠ **`상림3길`은 무대에서 쓰지 말 것.** 같은 길인데 번지에 따라 조회가 갈린다
    (시드 40건 중 실패 5건이 전부 이 길이다). 실패해도 등록은 되지만 **핀이 안 찍힌다**
- [ ] **AI 질문 변환 시연 문구는 키워드를 포함시킨다** — 폴백 키워드 표에 있는
      `난방`·`소음`·`수압`·`보안`·`관리비` 중 하나가 들어가야 한다
  - 예: **"겨울에 난방비가 얼마나 나올지 걱정돼요"**
  - ⚠ `"곰팡이가 걱정돼요"`처럼 표에 없는 말은, **AI가 실패해 폴백으로 내려갔을 때**
    엉뚱한 계약 조건 질문이 나온다(실측). AI가 정상일 때는 문제없지만 무대에서 확률을 낮춘다
