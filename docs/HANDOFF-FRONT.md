## 3. 코드만 봐서는 알 수 없는 판단

**여기가 이 문서의 핵심이다.** 되돌리기 전에 반드시 읽을 것.

### 3.1 방문 기록에 자동 저장을 쓰지 않았다
`lib/actions/visit.ts`의 `saveVisitResults`는 결과가 하나라도 들어오면 `markRecordedIfNeeded()`로 **`ready → recorded` 전이를 일으킨다.** 자동 저장을 넣으면 4택 버튼을 한 번만 눌러도 매물이 "기록 완료"가 되고, 국면 C(안전 점검)가 열리며, 절반만 기록한 매물이 계약 단계로 올라간다. R5 시점 원칙 위반이다.

→ 대신 **이탈 경고**(`use-unsaved-guard.ts`)와 "저장하지 않은 변경이 있어요" 배지로 처리했다.

### 3.2 `disabled` 대신 `ref`로 중복 요청을 막았다
React는 상태 변경을 다음 렌더에 반영한다. 빠르게 두 번 누르면 **버튼이 잠기기 전에 핸들러가 두 번 돈다.** 백엔드가 서버 로그로 확인한 실제 사고다 — 매물 2건 생성, 질문 2건 추가, 조사지 완성 시 두 번째 `setStatus`가 "허용되지 않는 전이"로 거부.

`ref`는 즉시 반영되므로 렌더를 기다리지 않는다. `_parts/use-mutations.ts`의 `inFlight` Set이 그 역할이다.

**키를 나눈 이유**: 전역으로 하나만 잡으면 서로 다른 체크박스를 연달아 누르는 정상 조작까지 막힌다(안전 점검 11개를 한 번에 하나씩 기다려야 함).

### 3.3 방문 기록에만 성공 칩이 없다
저장에 성공하면 **곧바로 비교 또는 안전 점검으로 넘어간다.** 성공 칩을 띄워도 즉시 화면이 바뀌어 보이지 않는다. 저장 중은 버튼이 "저장하는 중..."으로 알린다. 표시가 필요한 건 **실패뿐**이라 실패 칩만 둔다.

나머지 4개 화면(조사지·안전 점검·계약 후·비교)은 체크 하나하나가 개별 저장이라 "방금 그 클릭이 저장됐나?"를 계속 물어야 해서 성공 칩이 필요하다. **성격이 반대다.**

### 3.4 CSS 변수에 `--rc-` 접두사를 붙였다
프로토타입의 `--paper`·`--line`·`.card`·`.btn`을 그대로 쓰면 **shadcn/ui 토큰(`--card`, `--border`, `--input`, `--primary`)과 이름이 겹친다.** 전역 CSS라 충돌하면 `components/ui/`가 깨진다. 색값은 16진수 그대로 옮겼고 이름만 바꿨다.

`app/globals.css`의 `@theme`에 등록하지 않은 것은 백엔드 세션과의 충돌을 피하기 위한 초기 결정이었다. 지금은 병합됐으므로 승격을 검토할 수 있다.

**`components/map/PropertyMapPanel.tsx`가 `recheck-theme.css`를 import한다.** 토큰이 없으면 지도 색이 빠지기 때문이다. hex를 지도 쪽에 복사하면 값이 두 곳으로 갈라지고, 그건 `SCHOOL_ORIGIN` 교체 때 이미 한 번 겪은 실패 유형이다.

### 3.5 질문 출처 배지를 "문구"로 판별한다
`QuestionSource`는 계약상 `'bank' | 'ai'` 둘뿐이라 값을 늘릴 수 없다. AI 실패 시 템플릿 폴백은 `'bank'`로 저장하되, **질문 은행에 실제로 있는 문구인지**로 배지를 가른다 (`_parts/question-badge.tsx`).

| 조건 | 배지 |
|---|---|
| `source === 'ai'` | AI 변환 |
| `bank` + 은행에 있는 문구 | 질문 은행 |
| `bank` + 은행에 없는 문구 | 템플릿 |

세션 상태가 아니라 데이터로 판별하므로 새로고침해도 유지되고, 비교 화면의 협상 질문도 같은 경로로 "템플릿"이 된다.

### 3.6 홈 목록을 정렬하지 않는다
거리순·가격순 정렬은 그 자체가 순위 표시가 되어 R1에 걸린다. 등록 순서를 유지하고, **좌표를 못 얻은 매물만** "위치 미지정" 그룹으로 분리한다.

### 3.7 거래유형이 섞이면 가격 ▲▼를 그리지 않는다
전세 8,500만과 월세 45만은 같은 축의 값이 아니다. 화살표를 그리면 "전세가 189배 비싸다"로 읽힌다. 보증금도 같다 — 전세는 `deposit`이 0이라 "보증금이 가장 적다"는 틀린 읽기가 된다.

→ 대신 **초기 필요자금**과 **월 주거비** 두 축으로 안내한다. 이 두 행은 `rc-key-row`로 **같은 비중**으로 강조한다. 월 주거비만 강조하면 전세처럼 목돈이 묶이는 조건에서 자금 구속이 과소평가된다.

### 3.8 관리비 `0`은 `—`로 바꾸지 않았다 (면적은 바꿨다)
| 필드 | 처리 | 이유 |
|---|---|---|
| 면적 | `0` → `—`, ▲▼ 계산에서 제외 | 0㎡인 매물은 없다. 그대로 두면 미입력 매물이 "가장 좁은 매물"로 ▼ 표시된다 |
| 관리비 | `0`을 그대로 표시 | **관리비가 실제로 0원인 매물이 있다.** "모름"으로 적으면 사실과 다른 표기 = R8 위반. 대신 입력 라벨에서 "관리비가 없으면 0을 입력하세요"로 유도해 값의 의미를 사용자 의도로 확정한다 |
| 층수 | 처리 불필요 | `toText()`라 빈 값이 빈 문자열로 남는다. 0이 되지 않는다 |

### 3.9 국면 스텝은 갈 수 없는 단계를 링크로 만들지 않는다
서버가 `canTransition`으로 거부할 전이는 화면에서 미리 막는다. 잠긴 이유("조사지를 완성하면 열립니다")를 함께 적는다 — 그냥 비활성보다 낫다.

| 상태 | A 방문 준비 | B 방문 기록 | C 계약 |
|---|---|---|---|
| `prep`·`excluded` | 열림 | 잠김 | 잠김 |
| `ready` | 열림 | 열림 | 잠김 |
| `recorded`·`confirmed` | 열림 | 열림 | 열림 |

**프로토타입의 "방문 기록으로 건너뛰기" 버튼은 삭제했다.** `prep → recorded`는 서버가 거부하고, 조사지 없이 방문 기록을 쓰는 것 자체가 R5 위반이다.

### 3.10 카드 반응 기준은 뷰포트가 아니라 컨테이너다
`.rc-home-list`에 `container-type: inline-size`를 걸고 `@container (min-width: 560px)`로 카드 내부를 전환한다. 넓은 화면이라도 좌우 분할된 컬럼 안에서는 좁게 놓일 수 있어서, 뷰포트 기준으로는 표현할 수 없다.

### 3.11 `word-break: keep-all`은 장식이 아니다
한글은 기본값에서 음절 단위로 줄바꿈된다. 폭이 모자라면 "대구대학교"가 한 글자씩 세로로 쌓인다. **실제로 그 버그가 났었다.** 지우지 말 것.

### 3.12 인쇄 날짜는 `beforeprint`에서 만든다
서버에서 렌더하면 배포 서버가 UTC라 **새벽 시간대에 날짜가 하루 어긋난다.** `flushSync`로 즉시 반영하지 않으면 첫 인쇄물에 날짜가 빠진다. (`_parts/use-print-document.ts`)

같은 훅이 `document.title`을 바꿔 PDF 저장 파일명을 만든다(`리체크_조사지_{매물명}_{날짜}`). **공백과 하이픈은 일부러 남긴다** — `대구대원룸A`보다 `대구대 원룸 A`가 파일 목록에서 읽기 쉽고, 세 OS 모두 허용하는 문자다.

### 3.13 인쇄는 화면 안에서 자립한다
프로토타입은 문서 밖 `#print-area`에 그리고 `body > .wrap`을 숨겼다. 그 방식은 `app/layout.tsx`에 셸 클래스가 있어야 성립한다. 지금은 `rc-screen-only` / `rc-print-only` 쌍으로 화면 안에서 해결한다. **모달에도 `rc-screen-only`를 붙여야 한다** — 안 붙이면 모달을 연 채 인쇄할 때 점검표 위에 찍힌다.

### 3.14 새 콜백은 선택 prop으로 추가한다
`onDelete`·`onSetStatus`를 필수로 만들면 백엔드의 client 컴포넌트가 즉시 컴파일 에러를 낸다. **선택 prop으로 두고, 없으면 해당 버튼을 렌더하지 않는다.** 백엔드가 한 줄 연결하면 켜진다. 이 방식으로 빌드를 깨지 않고 기능을 넘겼다.

### 3.15 `CreatePropertyInput`을 `'use server'` 파일에서 type-only import 한다
`import type`은 SWC가 완전히 지운다. 런타임 import가 생기지 않으므로 Server Action을 부르는 것이 아니고, 계약이 바뀌면 타입이 깨져 바로 드러난다. 형태를 복사해 두면 계약과 갈라진다.

## 4. 같은 실수를 반복하지 않기 위한 주의사항

### 4.1 테스트 단언을 손으로 계산하지 말 것
**이 세션에서 세 번 틀렸다.**
- fixtures의 `progress: 78`을 그대로 믿고 단언 → 실제 계산값과 달랐음
- `101동`이 데이터인 줄 알았는데 **입력칸 placeholder**였음
- 안전 점검 필수 6건이 전부 미확인일 거라 단언 → fixtures에 이미 2건 체크돼 있었음

→ 기대값은 **`lib/`의 순수 함수와 fixtures에서 계산해서** 쓸 것. `expect(p.progress).toBe(calcProgress(p.visitChecks, p.questions))` 형태.

### 4.2 폴백만 검증하고 정상 경로를 빼먹지 말 것
AI·geocode 실패 경로만 테스트하다가, **"파싱 성공 + 저장 실패"** 조합에서 붙여넣기 탭이 영구히 잠기는 버그를 놓쳤다(스피너가 계속 돌고 에러도 안 보임). 정상 응답이 온 뒤의 실패도 경로다.

또 **"거래유형만 못 읽은 부분 성공"** 을 실패로 처리해 나머지 6개 필드를 버렸다. 실패/성공 이분법으로 나누지 말 것.

### 4.3 `order`는 관련된 것을 **전부** 지정할 것
`.rc-home-map`에만 `order`를 주고 `.rc-home-list`를 비워뒀더니 기본값 0과 동점이 되어 DOM 순서가 이겼고, 지도가 넓은 컬럼을 가져가 목록이 340px에 눌렸다. `min-width: 0`은 이미 있었고 원인이 아니었다.

### 4.4 정규식 문자 클래스를 눈으로 확인할 것
파일명 정리에서 `[/\\:*?"<>| -]`로 써서 **공백과 하이픈까지 지워버렸다.** 매물명이 붙어버린다.

### 4.5 bash heredoc에 복잡한 코드를 넣지 말 것
한글 + 백틱 + 따옴표가 섞인 패치를 heredoc으로 넣다가 파싱이 깨졌다. **스크립트를 scratchpad에 파일로 쓰고 실행할 것.**

### 4.6 `lib/`의 상수를 화면에 복사하지 말 것
기준점 이름을 4곳에 하드코딩했다가 백엔드가 `SCHOOL_ORIGIN.name`을 "대구대학교"로 바꿨을 때 따라오지 않았다. 지금은 전부 상수 참조다. 질문 은행 문구도 마찬가지 — `toggleBankQuestion`이 **text로 매칭**하므로 한 글자만 달라도 토글이 어긋난다.

### 4.7 렌더 중에 컴포넌트를 정의하지 말 것
`NumberRow`를 `CompareScreen` 안에 정의했다가 eslint에 걸렸다. 매 렌더마다 새 컴포넌트가 되어 상태가 초기화된다.

### 4.8 `useEffect` 안에서 직접 `setState` 하지 말 것
eslint가 막는다. 인쇄 날짜를 그렇게 넣으려다 걸렸고, 결과적으로 `beforeprint` 구독으로 바꾸면서 더 정확해졌다.

## 5. 검증 방법과 그 한계

### 할 수 있는 것
```bash
npx tsc --noEmit                                   # 타입
npx eslint components/screens components/map       # 린트
npm test                                           # lib·fixtures 유닛 테스트
```

**임시 vitest로 화면을 서버 렌더해 마크업을 검사할 수 있다.** 이 세션에서 계속 쓴 방법:

```bash
# 1) components/screens/scratch.test.tsx 작성 (renderToStaticMarkup 사용)
# 2) 프로젝트 루트에 vitest.scratch.mts 작성:
#    include: ['components/screens/**/*.test.tsx']
#    resolve.alias '@' → 프로젝트 루트
# 3) npx vitest run --config vitest.scratch.mts
# 4) 두 파일 모두 삭제   ← 반드시. 커밋에 들어가면 안 된다
```
`next/navigation`은 `vi.mock`으로 막는다: `useRouter: () => ({ push: vi.fn(), refresh: vi.fn() })`

### 할 수 없는 것 — 반드시 사용자에게 알릴 것
| 한계 | 영향 |
|---|---|
| **DOM 테스트 라이브러리 없음** (`@testing-library/react` 미설치) | **클릭 이후 동작을 검증할 수 없다.** 더블클릭 방지, 탭 전환, 이탈 경고, 모달 열림, prop 동기화 전부 코드 경로로만 확인했다 |
| **헤드리스 브라우저 없음** (playwright·puppeteer 미설치) | 시각 확인 불가. 1440/1024/**360** 폭은 CSS 규칙과 계산으로만 확인했다. 검수 기준 폭은 팀원 피드백에 따라 390 → **360px**로 낮췄다(2026-08-12). 백엔드가 만드는 스크린샷 러너가 이 폭을 찍는다 |
| 의존성 추가는 범위 밖 | 위 두 가지를 스스로 해결할 수 없다 |

→ **"확인했습니다"라고 쓰기 전에 무엇을 확인했는지 구분할 것.** 코드 경로 확인과 런타임 확인은 다르다. 이 세션에서 코드 경로만 보고 넘긴 버그를 백엔드가 실입력으로 두 번 잡아줬다.

### dev 서버
```bash
npx next dev -p 3010     # 3000·3001은 VS Code 포워딩 프로세스가 점유 중
```
**포트 3000이 아니면 카카오 JS 키 도메인 제한 때문에 지도가 폴백 리스트로 뜬다. 코드 문제가 아니다.** 3000을 쓰려면 VS Code PORTS 패널에서 포워딩을 해제해야 한다.

`next dev`가 실행될 때마다 `CLAUDE.md` 끝에 `<!-- BEGIN:nextjs-agent-rules -->` 블록을 자동으로 붙인다. **사람이 고친 것이 아니다.** 커밋하지 말 것.

### 7.2 문구를 고칠 때

**어떤 문구가 어디 소유인지 먼저 확인할 것.** 소유자가 아닌 곳에서 고치면 값이 두 곳으로 갈라진다.

| 문구 | 소유 | 화면에서 고칠 수 있나 |
|---|---|---|
| 확인 항목·안전 점검·계약 절차의 제목·설명 | `lib/rules.ts` (서버가 `visitChecks[].title/description`으로 내려줌) | **아니오 — 보고** |
| 질문 은행 문구 | `lib/rules.ts`의 `QUESTION_BANK` | **아니오 — 보고** |
| 거리 표기 (`formatDistanceLabel`, `DISTANCE_NOTICE`, 기준점 이름) | `lib/geo.ts` | **아니오 — 상수 참조만** |
| 금융 면책·가정·전환 안내 | `lib/finance.ts` | **아니오 — 상수 참조만** |
| 지도 하단 고정 문구·핀 라벨 | `components/map/status-pin.ts` | **아니오** |
| 화면 안내·라벨·버튼·빈 상태·에러 문구 | 각 화면 파일 | **예** |

**질문 은행 문구는 매칭 키다.** `toggleBankQuestion`이 `text`로 매칭하므로 한 글자만 바꿔도 **이미 저장된 질문의 토글이 어긋난다.** 수정을 건의할 때 "기존 데이터와 매칭이 깨진다"는 사실을 반드시 함께 보고할 것.

**바꾼 문구는 R1 금칙어와 대조할 것.** `lib/rules.ts`의 `BANNED_PHRASES`가 목록이다 — 추천 / 안전합니다 / 위험합니다 / 유리합니다 / 불리합니다 / 더 낫 / 가장 좋 / 적합합니다 / 점수 등.

**규약 문서 위치**
- `components/screens/README.md` — 출처 배지, 거리 표기, 전환 계산기 규약
- `CLAUDE.md`의 "UI 규약" 절 — 배지·면책·비교표 범례·터치 타깃

### 7.3 "무슨 말인지 모르겠다"는 용어를 다룰 때

**나올 만한 용어**: 근저당 · 선순위 · 전세가율 · 대항력 · 확정일자 · 신탁 등기 · 위반건축물(근생) · 전월세전환율 · 우선변제권

원칙은 하나다. **설명은 하되 판정하지 않는다. (R1)**

| | |
|---|---|
| ✅ 한다 | 용어를 풀어쓴다. 어디서 확인하는지 알려준다. 무엇을 보는 항목인지 말한다 |
| ❌ 안 한다 | "있으면 위험합니다" 같은 결론. "N% 넘으면 조심하세요" 같은 **숫자 기준**. "이 매물은 ~합니다"처럼 특정 매물에 붙는 평가 |

```
✗ 근저당이 있으면 보증금을 못 받을 수 있어 위험합니다.
✓ 근저당은 그 집을 담보로 빌린 돈이에요. 등기부 을구에서 금액과 순위를 확인하세요.

✗ 전세가율 80%가 넘으면 위험합니다.
✓ 전세가율은 전세금 ÷ 매매시세예요. 국토부 실거래가 공개시스템에서 주변 시세를 조회해 직접 계산합니다.
```

**숫자 기준을 만드는 것이 특히 위험하다.** 그 숫자는 서비스가 제시한 기준이 되고, 근거가 없으면 R8(추측한 사실)까지 함께 위반한다. 기준이 꼭 필요하면 **출처와 함께 사용자에게 확인받을 것.**

**어디에 쓰나**
- 규칙 항목의 `description`은 `lib/rules.ts` 소유다. 그 안의 용어가 어렵다면 **고치지 말고 보고**한다.
- 화면은 **보조 설명을 덧붙일 수 있다.** 예: 안전 점검 항목 아래 접이식 용어 설명, 입력칸 옆 도움말. 이건 화면 파일에서 자유롭게 한다.
- 새 설명 문구도 `SourceBadge`가 필요하다면 `rule`(규칙 기반)이다. AI가 만든 것이 아니므로 `ai` 배지를 붙이면 거짓이다.
