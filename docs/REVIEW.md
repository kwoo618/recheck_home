# REVIEW.md — 계획서 자체 검토 체크리스트

> **이 문서의 용도**: Claude Code가 계획서를 낼 때 이 표로 스스로 검토해 **함께 제출**한다 (`docs/WORKFLOW.md` §3).
> 항목마다 **✅ 통과 / ⚠ 확인 필요 / ❌ 위반** 중 하나와 **근거 한 줄**을 적는다. 근거 없는 ✅는 쓰지 않는다.
> ⚠·❌가 하나라도 있으면 "판단 필요"로 올린다. ❌는 계획을 고치기 전에는 실행하지 않는다.

---

## 답하는 형식

```
| 항목 | 결과 | 근거 |
|---|---|---|
| A1 | ✅ | V2-PLAN §4-1 파이프라인 "대조" 행 |
| … | | |
```

---

## A. 범위

| # | 질문 |
|---|---|
| A1 | `docs/V2-PLAN.md`에 있는 항목인가? (절 번호로 근거) |
| A2 | `CLAUDE.md` "하지 말 것"에 닿는가? |
| A3 | 요청받지 않은 겸사겸사 변경이 섞였는가? (섞였으면 빼고 STATUS에 적는다) |

## B. 파일 경계

| # | 질문 |
|---|---|
| B1 | 바꾸는 파일이 전부 이 세션의 담당 디렉터리 안인가? |
| B2 | `CLAUDE.md` "건드리지 말 것"(`drizzle/`·`db/migrations/`·`docs/v1/**`·`screenshots/v1-baseline/`·`.env*` 등)에 닿는가? |
| B3 | 기존 테스트를 고치려 하는가? (실패하면 코드를 고친다. 의도적 변경이면 승인) |

## C. 승인

아래 중 하나라도 계획에 있으면 ⚠로 표시하고 무엇인지 적는다.

| # | 질문 |
|---|---|
| C1 | `db/schema.ts` 변경 · 마이그레이션 생성·실행 |
| C2 | 배포 (`main` 푸시 · 머지) |
| C3 | `lib/rules.ts` · `finance.ts` · `geo.ts` · `compare/*`의 **값** 변경 |
| C4 | `docs/API-V2.md` 계약 변경 |
| C5 | AI 지점 추가 (R3) |
| C6 | 온디바이스 자산 예산 2.0MB 초과 (Tesseract·서버 OCR 재개 포함) |

## D. 규칙

| # | 질문 |
|---|---|
| D1 | **R1** 판정형 출력이 생기는가? **오탐도 판정이다** — 틀린 "다릅니다"가 나올 경로가 있는가? |
| D2 | **R2** 순수 함수 파일에 AI 호출·fetch·DB·랜덤·`Date.now()`가 들어가는가? |
| D3 | **R4** 새 외부 의존성마다 폴백과 `200 + {ok:false}`가 있는가? |
| D4 | **R7** `address_detail`·`special_terms` 원문이 지도·PDF·대조 결과·인쇄·공유에 렌더링되는가? |
| D5 | **R8** 추측한 수치·명칭·한도를 코드나 문구에 넣는가? 구조화가 못 찾은 값을 `null` 대신 채우는가? |
| D6 | **R10** 주소에 `different`를 낼 수 있는가? |
| D7 | **R11** 규칙을 바꾸는가? 바꾼다면 `docs/INFRA.md` 결정 로그 행이 계획에 있는가? |
