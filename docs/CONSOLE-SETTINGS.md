## 1. Neon (PostgreSQL)

| 항목 | 값 |
|---|---|
| 프로젝트명 | `recheck` |
| 리전 | **AWS Asia Pacific 1 (Singapore) / ap-southeast-1** |
| Postgres | 18 |
| 기본 브랜치명 | **`production`** (`main` 아님) |
| 오토스케일 | `.25 ↔ 2 CU` (기본값 유지) |
| 연결 방식 | pooled (호스트에 `-pooler` 포함) → `DATABASE_URL` |

**리전을 도쿄로 못 한 이유**: Neon 리전 목록에 도쿄가 없다. Singapore가 한국에서 가장 가까운 AWS 리전. 리전은 생성 후 변경 불가.

**무료 한도** (2026-08-11 대시보드 확인)
- Compute 100 CU-hrs/월 · Storage 0.5 GB · Network transfer 5 GB · Branch 10개
- 최소 0.25 CU 기준 약 400시간 → 데모 규모에선 여유

⚠️ **scale-to-zero 있음.** 무요청 상태가 이어지면 컴퓨트가 정지하고, 재기동 시 콜드 스타트가 붙는다.
**발표 직전 앱 1회 접속으로 웜업 필요.**

## 2. 카카오 개발자

### ⚠️ 앱이 두 개다 — `1540296`만 쓴다

| 앱 ID | 상태 |
|---|---|
| **1540296** | **사용 중.** 카카오맵 무료 쿼터가 여기에 배정됨 |
| 1540243 | 미사용. 실수로 먼저 만든 것. D4 이후 정리 예정 |

무료 쿼터는 "첫 번째로 카카오맵 API를 활성화한 앱"에만 주어지고,
**비활성화해도 이전 불가한 1회성 배정**이다. 그래서 `1540296`이 확정.

### 키와 도메인 등록 위치

| 키 | 환경변수 | 비고 |
|---|---|---|
| JavaScript 키 | `NEXT_PUBLIC_KAKAO_MAP_KEY` | 클라이언트 번들에 노출됨. **도메인 제한이 유일한 방어선** |
| REST API 키 | `KAKAO_REST_KEY` | 서버 전용. 도메인 등록 불필요 |
| 어드민 키 | — | **절대 사용 금지.** 앱 전체 제어권 |

**도메인 등록 경로** (헷갈리기 쉬움 — "제품 링크 관리"가 아니다)
```
앱 1540296 > 플랫폼 키 > JavaScript 키 > JavaScript SDK 도메인
```
등록된 값:
- `http://localhost:3000`
- `https://recheck-home.vercel.app`

⚠️ 로컬 개발 시 **반드시 3000 포트**로 띄워야 한다. 다른 포트면 SDK가 401
(`domain mismatched!`)로 거부되고 지도가 폴백 리스트로 뜬다. **코드 문제가 아니다.**

### 한도

| 항목 | 값 |
|---|---|
| 지도 SDK | 1일 300,000회 (2026-08-11 확인) |
| 로컬 API (주소→좌표) | **미확인.** 위 30만회는 여기 적용 안 됨 |
| 유료 API | **"사용 안 함" 유지** — 한도 초과 시 과금이 아니라 차단 |

"사용 안 함"을 유지하는 이유: 학생 프로젝트에서 의도치 않은 청구를 막는 쪽이 낫고,
R4 폴백(지도 실패→리스트 뷰, 좌표 실패→`latitude: null`)이 있어 초과해도 핵심 흐름은 산다.

### 주소 검색은 키가 필요 없다
Daum 우편번호 서비스는 스크립트만 삽입하면 동작한다. 키 발급·도메인 등록 불필요.
REST 키가 필요한 건 그 뒤 좌표 변환(로컬 API)뿐이다.

## 3. Gemini

| 항목 | 값 |
|---|---|
| 기본 모델 | `gemini-3.5-flash` |
| 폴백 모델 | `gemini-3.5-flash-lite` |
| 타임아웃 | 12,000 ms |
| 키 | `GEMINI_API_KEY` (서버 전용, `NEXT_PUBLIC_` 금지) |

**`gemini-2.5-flash` 계열은 쓸 수 없다.** 신규 계정에 404
(`no longer available to new users.`)로 막혀 있다.

**모델 선정 근거** (실측)

| 모델 | 응답 시간 |
|---|---|
| `gemini-3.5-flash-lite` | 1.1s |
| `gemini-3.5-flash` | 3.7s |
| `gemini-3.6-flash` | 5.1s |
| `gemini-flash-latest` | 6.4s |

- `*-latest` 별칭 배제: 5~6초대로 타임아웃에 근접하고, 자동 갱신이라 발표 당일 동작이 바뀔 수 있다
- preview 버전 배제: 예고 없이 변경·중단될 수 있다
- `flash-lite`로 기본을 바꾸지 말 것: 빨라지지만 질문 품질이 떨어진다. 우려→질문 변환은 R3의 핵심이라 품질을 포기할 자리가 아니다

**무료 티어 RPM/RPD는 미확인.** 문서에서 못 찾았다. 검증 중 20여 회 호출로는 한도에 걸리지 않았다.

## 4. Vercel

| 항목 | 값 |
|---|---|
| 팀 | `recheck` (Hobby) |
| 프로젝트명 | `recheck-home` |
| 배포 URL | `https://recheck-home.vercel.app` |
| 함수 리전 | **`sin1` (Singapore)** |
| 환경변수 | 4개 등록 완료 (Production·Preview) |

**리전을 서울(`icn1`)이 아니라 `sin1`로 한 이유**
Neon이 싱가포르에 있다. Server Action 1회당 DB를 여러 번 왕복하므로,
함수를 DB 옆에 두면 왕복이 리전 내부에서 끝나고 사용자↔싱가포르 구간은
요청당 1회만 발생한다. 서울에 두면 매 왕복이 서울↔싱가포르가 된다.
Hobby 플랜은 리전 1개 제한이라 분산 불가.

확인 방법: 응답 헤더 `X-Vercel-Id: icn1::sin1::`

## 5. GitHub / 로컬 환경

| 항목 | 값 |
|---|---|
| 저장소 | `kwoo618/recheck_home` (**private**) |
| 브랜치 | `main` (배포) / `feat/screens` (프론트 작업) |
| 로컬 — 백엔드 | `E:\project\recheck` → `main` |
| 로컬 — 프론트 | `E:\project\recheck-front` → `feat/screens` (git worktree) |

**private을 유지하는 이유**: public 저장소는 봇이 상시 스캔해서 키가 실수로
한 번 커밋되면 푸시 직후 수 분 내에 긁힌다. amend로 지워도 늦다.
발표 자료에 링크를 넣을 거라면 D4 오전에 전환하되, 그 전에 히스토리 감사를 할 것.

## 6. 자주 막히는 지점

| 증상 | 원인 | 해결 |
|---|---|---|
| 지도가 리스트로만 뜸 | 3000이 아닌 포트에서 실행 중 | VS Code PORTS 패널에서 3000 Stop Forwarding, 또는 VS Code 재시작 |
| `localhost:3000`이 `Index of /`를 반환 | VS Code 포트 포워딩이 3000 점유 | 위와 동일 |
| 배포본에서 지도만 안 뜸 | 카카오 도메인 미등록 | 앱 `1540296`의 JavaScript SDK 도메인 확인 |
| `drizzle-kit push`가 DDL에서 실패 | pooled 연결 제약 | Connect 모달에서 pooling 끈 문자열로 마이그레이션만 실행 |
| 발표 첫 화면이 수 초 멈춤 | Neon scale-to-zero 콜드 스타트 | 발표 직전 1회 접속으로 웜업 |
