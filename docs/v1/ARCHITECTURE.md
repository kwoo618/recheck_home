# 리:체크 — 기술 구조

> ⚠️ v1 기술 구조. v2는 AI 지점이 5개다(문서 구조화 ④·확인 도우미 ⑤ 추가).
> "AI는 3지점" 서술과 다이어그램은 v1 기준. 단일 소스는 lib/ai/touchpoints.ts.
> 기기 OCR·IndexedDB 원본 보관(R9)·오프라인 경로는 이 문서에 없다. 폴백 표는 v2에서도 유효하다.

> **이 문서의 용도**: 발표 기술 슬라이드의 원본.
> 비전공자가 읽고 그대로 슬라이드로 옮길 수 있게 썼다. 다이어그램은 전부 텍스트다.

## 0. 한 문장

**규칙이 판정하고, AI는 3지점에서 자유 텍스트만 다루고, 판단은 사용자가 한다.**
외부 서비스가 하나씩 죽어도 핵심 검증 흐름은 그대로 동작한다.

## 1. 스택과 고른 이유

| 영역 | 선택 | 왜 이걸 골랐나 |
|---|---|---|
| 프레임워크 | **Next.js (App Router)** + TypeScript | 화면과 서버 로직이 한 저장소에 있어 4일 일정에 맞다. 서버 컴포넌트라 DB 조회 결과를 바로 렌더할 수 있고, 키가 필요한 호출은 전부 서버에 남는다 |
| DB | **Neon** (서버리스 PostgreSQL) | 무료 티어에 scale-to-zero. 쓰지 않을 때 요금이 0이다. 대신 첫 요청에 콜드 스타트가 붙어 **발표 직전 웜업이 필요하다** |
| ORM | **Drizzle** | Neon의 HTTP 드라이버를 공식 지원하고 서버리스에서 가볍다. Prisma도 가능했지만 콜드 스타트·번들 부담이 있다 |
| 지도 | **카카오맵 JS SDK** | 국내 주소·건물 데이터가 정확하다. 클라이언트 전용이라 키에 **도메인 제한**을 걸어야 한다 |
| 주소 검색 | 카카오(다음) **우편번호 서비스** | 키·도메인 등록 없이 스크립트 임베드만으로 동작한다 |
| 주소 → 좌표 | 카카오 **로컬 API** | REST 키가 필요해 **서버에서만** 호출한다 |
| AI | **Gemini** (무료 티어) | 자유 텍스트 이해가 필요한 3지점에만 쓴다. 무료 한도 안에서 데모가 가능하다 |
| 배포 | **Vercel** (Hobby) | `git push`가 곧 배포다. 4일 일정에서 배포 파이프라인에 시간을 쓰지 않았다 |
| 스타일 | Tailwind CSS | 인쇄 대응(`print:`)이 유틸리티로 해결된다 |
| PDF | 인쇄 전용 스타일시트 + 브라우저 인쇄 | 별도 비용·라이브러리가 없다 |
| 인증 | 익명 세션 (UUID 쿠키) | 로그인을 만들 시간에 검증 흐름을 만들었다. 대신 **브라우저를 바꾸면 다른 사람**이다 |

### 왜 Vercel 함수 리전을 서울(icn1)이 아니라 싱가포르(sin1)로 골랐나

**DB가 싱가포르에 있기 때문이다.** Neon에는 도쿄·서울 리전이 없어 한국에서 가장 가까운 `ap-southeast-1`(싱가포르)을 썼다.

```
[함수를 서울에 두면]                    [함수를 싱가포르에 두면 — 선택]
사용자 ─(가까움)─ 서울 함수             사용자 ─(멂, 요청당 1회)─ 싱가포르 함수
                    │                                              │
        서울 ↔ 싱가포르 왕복 × N번           싱가포르 안에서 왕복 × N번 (거의 0)
                    │                                              │
              싱가포르 DB                                    싱가포르 DB
```

핵심은 **화면 하나를 그리는 데 DB를 여러 번 왕복한다**는 점이다. 매물 목록 + 조사지 + 질문 + 금융 프로필처럼 조회가 여러 번 일어난다.
함수를 서울에 두면 그 왕복이 **전부** 국제 구간을 탄다. 함수를 DB 옆에 두면 국제 구간은 **사용자 ↔ 함수 1회**로 끝나고 나머지는 리전 내부에서 끝난다.

> 실측: `X-Vercel-Id: icn1::sin1::…` — 엣지는 서울에서 받고, 함수 실행은 싱가포르다.
> 웜 상태 응답 0.26~0.48초.

## 2. 데이터 흐름 — 요청부터 렌더까지

```
[브라우저]
   │  ① 페이지 요청 (예: 홈 "/")
   ▼
[proxy.ts]  ─ 세션 쿠키(rc_session)가 없으면 새 UUID 발급
   │           · 서버 컴포넌트는 "렌더 중"에 쿠키를 쓸 수 없어서 이 앞단이 필요하다
   │           · /api/** 는 여기서 제외한다 (이유는 §5)
   ▼
[서버 컴포넌트]  app/page.tsx
   │  ② 쿠키 → users 행 보장 → userId
   │  ③ Server Action 으로 데이터 조회 (listProperties)
   │        └ Drizzle → Neon (같은 리전, HTTP)
   │  ④ 순수 함수로 계산
   │        lib/geo.ts      거리·진행률
   │        lib/rules.ts    확인 항목 선정
   │        lib/finance.ts  금융·사글세 계산
   │  ⑤ 화면에 넘길 값만 추려서 props 로 전달
   │        withoutAddressDetail()  동/호수 제거   ← R7
   │        toMapProperties()       지도에 6개 필드만
   ▼
[클라이언트 컴포넌트]  components/screens/**
   │  ⑥ 받은 props 를 그리기만 한다. 계산하지 않는다
   │  ⑦ 지도는 next/dynamic + ssr:false 로 브라우저에서만 로드
   ▼
[사용자 입력]
   │  ⑧ Server Action 호출 (createProperty · saveVisitResults · …)
   │        · 실패해도 예외를 던지지 않고 { ok:false, error } 를 돌려준다
   │        · 상태 전이는 canTransition() 이 서버에서 검증
   ▼
[Neon PostgreSQL]
```

**핵심 두 가지**

1. **계산은 전부 서버에서 끝난다.** 화면은 숫자를 만들지 않고 받은 값을 그린다. 같은 입력이면 누가 봐도 같은 결과가 나온다.
2. **클라이언트에 넘기는 값을 줄인다.** 서버 컴포넌트가 넘긴 props는 렌더하지 않아도 페이지 소스에 직렬화돼 남는다. 그래서 상세주소(동/호수)는 **넘기기 전에 제거**한다.

### AI를 쓸 때만 별도 경로

```
[브라우저] ──POST──> [/api/ai/parse | questions | summary] ──> [Gemini]
                            │
                            ├ 프롬프트에 "판정 금지" 지시
                            ├ 응답을 containsBanned() 로 거름     ← R1 2차 방어선
                            ├ 실패·타임아웃 → 템플릿 폴백
                            └ 항상 HTTP 200 + { ok: false } 로 응답
```

> 라우트가 **실패해도 200을 돌려주는 이유**: 프론트가 `try/catch` 없이 `ok`만 보고 폴백 UI를 그리면 되게 하려는 것이다. 비전공 팀원이 화면을 만들었다.

## 3. 외부 의존성 4종과 폴백

**어느 하나가 죽어도 "매물을 등록하고 확인 항목을 만들고 기록하고 비교한다"는 핵심 흐름은 끊기지 않는다.**

| 외부 서비스 | 하는 일 | 죽으면 | 사용자가 보는 것 |
|---|---|---|---|
| **카카오맵 SDK** | 지도·핀 렌더 | 지도 영역을 **리스트로 대체** | "지도를 불러오지 못했습니다" + 매물 목록. 검증·비교·인쇄 정상 |
| **카카오 로컬 API** | 주소 → 좌표 | 좌표를 **null로 저장** | 매물은 정상 등록됨. "위치 미지정" 그룹으로 분류 |
| **Gemini** | 붙여넣기 파싱 · 질문 변환 · 차이 요약 | **템플릿(질문 은행)으로 대체** | 질문이 그대로 나온다. **출처 배지가 `AI` → `규칙 기반`으로 바뀌는 것**이 유일한 차이 |
| **Neon** | 데이터 저장 | 대체 불가 (핵심 저장소) | scale-to-zero 콜드 스타트는 발표 직전 웜업으로 대응 |

> 실측 근거: Gemini 키를 비운 채 호출해 템플릿 질문이 나오는 것을 배포본에서 확인했다.
> 미등록 도메인에서 지도 SDK가 `401 domain mismatched!`로 거부되는 것도 확인했다(도메인 제한이 실제로 걸려 있다는 뜻이다).

## 4. 결정론 코드와 AI의 경계 — 이 서비스의 핵심 설계

```
┌──────────────────────────── 규칙 (결정론 · 순수 함수) ───────────────────────────┐
│  lib/rules.ts    확인 항목 선정 · 안전 점검 분류 · 질문 은행 · 상태 전이 검증      │
│  lib/finance.ts  금융 계산 · 보증금↔월세 전환 · 사글세 월 환산                    │
│  lib/geo.ts      거리 계산 · 진행률 집계                                          │
│                                                                                   │
│  · AI 호출 없음 · fetch 없음 · DB 접근 없음 · 랜덤 없음 · Date.now() 없음         │
│  · 같은 입력 → 항상 같은 출력. 유닛 테스트 대상                                   │
└───────────────────────────────────────────────────────────────────────────────────┘
                                     ▲
                                     │  숫자·목록·분류는 전부 이쪽에서 나온다
                                     │
┌──────────────────────────── AI (Gemini) — 딱 3지점 ──────────────────────────────┐
│  ① 붙여넣은 매물 텍스트 → 구조화     "보증금 500/월 45" 같은 자유 문장을 필드로   │
│  ② 우려사항 → 질문 변환              "반려묘랑 살아야 해요" → 중개사에게 할 질문  │
│  ③ 조사 기록 차이 요약               두 매물의 답변 차이를 문장으로               │
│                                                                                   │
│  · 셋 다 "자유 텍스트를 이해하는 일"이다. 판정·점수·순위를 만들지 않는다          │
│  · 프롬프트에 판정 금지 지시 + 출력을 금칙어 필터로 거름 (이중 장치)              │
└───────────────────────────────────────────────────────────────────────────────────┘
                                     ▲
                                     │
┌──────────────────────────────── 사용자 ──────────────────────────────────────────┐
│  정보 확인·수정 · 현장 조사 · 답변 기록 · 비교 · **최종 선택과 계약 판단**        │
└───────────────────────────────────────────────────────────────────────────────────┘
```

**"AI가 판단하지 않는다"를 증명하는 방법**

`/admin` 대시보드가 **매물 1건당 규칙 항목 수와 AI 질문 수**를 나란히 보여준다.
절대값이 아니라 매물당으로 정규화했기 때문에 데이터가 늘어도 이 비율은 흔들리지 않는다.

또 하나의 증거: `/api/ai/parse`에 **"이 매물 진짜 좋아요 강력 추천합니다 안전합니다"**를 넣으면
`{"ok":false,"reason":"인식된 항목이 없습니다."}` — **한 필드도 통과하지 못한다.**

## 5. 상태 모델 — 이게 곧 퍼널이다

```
  prep  ──── 정보 확인 + 조사지 완성 ────>  ready
  (등록 직후)                              (방문 대기)
                                              │
                                         기록 저장
                                              ▼
                                          recorded  ──── 확정 ────>  confirmed
                                          (기록 완료)  <─── 확정 취소 ──   (계약 확정)
       ┌──────────────────────────────────────┤
       │                                   제외
       ▼                                      ▼
     prep  <──── 복구 ────────────────────  excluded
```

- **전이 검증은 서버에서 한다** — `canTransition()`. 허용되지 않은 전이는 `{ok:false}`로 거절한다.
- **활성 매물 = `confirmed`·`excluded`가 아닌 것.** 비교 화면은 활성 매물 2건 이상일 때 열린다.
- **진행률 = (결과 입력된 확인 항목 + 답변된 질문) ÷ 전체.** 점수가 아니라 집계다.
- 지도 핀 색상이 이 상태에 1:1 대응한다(색만이 아니라 텍스트 라벨을 함께 표시한다).

**설계 이득**: 별도 이벤트 테이블 없이 `GROUP BY status` 한 번으로 퍼널이 나온다.
단, 상태는 "현재 위치"라 그대로 세면 계단이 아니라 분포가 되므로 **누적으로** 센다.

> 한계도 같이 적는다: 제외된 매물은 **제외 시점의 진행 단계를 기록하지 않아** 등록 단계까지만 집계된다. 뒤 단계 전환율이 실제보다 낮게 나올 수 있고, 대시보드 화면에 그렇게 적어 뒀다.

## 6. 보안·개인정보에서 실제로 한 것

| 지킨 것 | 어떻게 |
|---|---|
| 비밀키가 브라우저에 안 간다 | Gemini 키·DB URL·카카오 REST 키는 **서버에서만** 쓴다. 클라이언트에 나가는 것은 **도메인 제한이 걸린 지도 JS 키** 하나뿐 |
| 상세주소(동/호수)를 노출하지 않는다 | 저장은 하되 지도·PDF·공유 화면에 렌더하지 않는다. 더해서 **클라이언트로 넘기는 props에서 아예 제거**했다 — 렌더하지 않아도 페이지 소스에는 남기 때문 |
| API 라우트가 무단 사용되지 않는다 | `proxy.ts`가 `/api/**`에는 세션 쿠키를 **발급하지 않는다.** 발급하면 라우트의 세션 검사가 항상 통과해 "보호처럼 보이는 죽은 코드"가 된다 |
| 남의 데이터에 접근할 수 없다 | 모든 액션이 세션 소유권을 먼저 검증한다. 남의 매물은 "권한 없음"이 아니라 **"없는 것"**으로 답한다(존재 사실 자체를 흘리지 않는다) |
| 대시보드가 개인정보를 다루지 않는다 | 별칭·상세주소·메모·답변 원문을 **select 자체를 하지 않는다.** 주소는 읍·면·동까지만 집계에 쓴다 |

## 7. 검증 방법

| 도구 | 무엇을 잡나 | 규모 |
|---|---|---|
| `tsc` · `eslint` | 타입·정적 오류 | 상시 |
| `vitest` | **순수 함수의 결정론** — 규칙 선정, 금융 계산, 거리, 더미 데이터 정합성 | **217건** (DB 없이 항상 실행 가능) |
| **스크린샷 러너** (`tests/e2e`) | **렌더 결과** — 3뷰포트 × 전 화면 + 인쇄 레이아웃 | 실패·가로 스크롤·콘솔 에러 자동 수집 |
| 실 DB 통합 검증 | Server Action이 실제로 저장하는지 | 필요할 때 임시 작성 후 삭제 |

> 스크린샷 러너는 **단언(assertion)을 쓰지 않는다.** 사진을 남기고 판단은 사람이 한다.
> 만든 이유: 이 프로젝트의 AI 세션들은 브라우저를 볼 수 없어서, 실사용 점검 21건 중 절반이 "확인 못 함"으로 남았기 때문이다.
> 실제로 이 러너가 **모바일 가로 스크롤 3건**과 **보증금 500만 월세에서 근저당 확인 항목이 누락되던 버그**를 잡았다.

## 8. 슬라이드로 옮길 때 쓸 문장
