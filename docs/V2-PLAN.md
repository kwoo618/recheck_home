## 4. 기능 명세

### 4-1. 문서 대조 (A) [Must]

**입력** 3종 중 2종 이상.
- 광고 캡처: 이미지 — 이미지 텍스트 추출(OCR)이 보류라 **확인 화면 수기 입력**
- 등기부등본: 인터넷등기소 PDF (촬영 이미지는 OCR 보류)
- 계약서: 표준 임대차계약서 PDF (촬영은 OCR 보류). 초안이든 본계약이든 동일 처리

**파이프라인**

| 단계 | 위치 | 구현 |
|---|---|---|
| 업로드 | 클라이언트 | IndexedDB 저장. 서버 전송 없음. `documents`에는 종류·시각·OCR 출처만 |
| PDF 텍스트 추출 | 클라이언트 | **1순위 경로.** pdf.js `getTextContent()`로 텍스트 레이어 직접 추출. bbox는 transform으로 계산. 텍스트 레이어가 없으면 확인 화면 수기 (인터넷등기소 PDF가 어느 쪽인지는 V2-STATUS §4 실측) |
| OCR | **보류** (2026-09-29, 도입은 별도 승인) | 설계는 유지: 기기 1차(Tesseract.js, `tessdata_fast/kor` 자체 호스팅 — V2-TECH-REVIEW §2) → 실패·저신뢰 시 **동의 후 서버**(Gemini 이미지 입력, 처리 후 폐기). 기기 OCR은 토큰 bbox 보관, 서버 OCR은 bbox 없음 → "위치 추정" |
| 구조화 | 서버, 지점 ④ | 스키마 강제 · 판정 금지 · `null` 허용. 전송 전 주민번호·생년월일 마스킹. **전 필드 편집 가능한 확인 화면** 필수 경유 |
| 대조 | 서버, `lib/compare/*` 순수 함수 | 정규화(㎡↔평, 공백·괄호, 금액 단위, 성명 공백) 후 필드별 `same / different / missing`. 심각도·순위 없음. 유닛 테스트 |
| 표시 | 클라이언트 | `"{docA}에는 [{a}], {docB}에는 [{b}]로 기재되어 있습니다"`. 중립 톤, 나란히, 색 강조 없음. 항목 탭 → bbox 하이라이트. 면책 상시 |

| 근저당 | 등기부 | — | 합산 금액만 표시. `missing` 아님, 단독 표시 항목 |

### 4-2. 불일치 → 질문 (A′) [Must]
`discrepancies` 행 → 지점 ② → 조사지 "문서에서 확인된 차이" 섹션. 배지 `AI`. 폴백 템플릿 `"{field}가 {docA}와 {docB}에서 다릅니다. 어느 쪽이 맞는지 확인해 주세요."`

### 4-3. 문서 준비 상태 패널 [Must]
`"등기부 ○ · 광고 ○ · 계약서 ×"`. 2종 미만이면 대조 버튼 비활성 + 이유.

### 4-4. 온디바이스·오프라인 (D) [Must]
PWA(manifest + SW) · 조사지·방문 기록 오프라인 캐시 · 입력은 IndexedDB 큐 → 온라인 시 Server Action 재전송(마지막 저장 우선) · 원본 IndexedDB 보관, 사용자 삭제 가능.
경계: 기기 = 원본 보관·PDF 텍스트 추출·오프라인 조사지 / 서버 = 구조화·대조·계산.

### 4-5. 확인 도우미 (⑤) [Should · 나중]
답함: 용어(28건) · 절차 · 사용법 · "다음에 뭐 해요?"(상태 모델). 되돌림: 판단 질문 → "판단하지 않습니다 + 미확인 항목 목록". 안 함: 시세·법률 자문. 근거 자료 전체를 프롬프트에 포함(RAG 불필요). 답변마다 `근거: {섹션}`.

### 4-6. 계약서 확인 항목 [Must, 규칙 기반]

계약서 대조 결과와 별개로, 계약 전 안전 점검 화면(`/safety`)에 **계약서 전용 확인 항목**을 규칙(`lib/rules.ts`)으로 추가한다. 출처 배지 `규칙 기반`. 전부 존재/확인 여부만 묻고 판정하지 않는다.

| 항목 | 자동 채움 (추출 필드 있으면) | 사용자 확인 |
|---|---|---|
| 목적물 표시(소재지·면적·용도)가 등기부 표제부와 같은가 | 대조 결과 연결 | — |
| 보증금이 한글·숫자로 나란히 적혀 있고 두 표기가 같은가 | 대조 결과 연결 | 빈칸 없이 채워졌는지 |
| 월세 금액·지급일·지급 방법이 적혀 있는가 | `rent_due_day`·`rent_method` null 여부 | — |
| 계약금 입금 계좌 예금주가 등기부 소유자와 같은가 | 대조 결과 연결 | 실제 이체 시 재확인 |
| 잔금일이 이사(입주) 날짜와 같은가 | `balance_date` 표시 | 이사 날짜 입력 후 비교 (사용자 입력) |
| 임대차 기간 시작·종료일이 적혀 있는가 | `lease_start`·`lease_end` | — |
| 임대인 성명이 등기부 소유자와 같은가 · 신분증으로 대조했는가 | 대조 결과 연결 | 신분증 대조 여부 |
| 대리인 계약이면 위임장 · 인감증명서 · 소유자 신분증 사본 3종을 확인했는가 | `agent_flag` true일 때만 표시 | 3종 각각 체크 |
| 특약에 보증보험 가입 조항이 있는가 | `special_terms` 키워드 후보 표시 | 사용자 확인 |
| 특약에 잔금일까지 권리 변동 시 해제 조항이 있는가 | 키워드 후보 표시 | 사용자 확인 |
| 특약에 원상복구 범위(통상 마모 제외) 조항이 있는가 | 키워드 후보 표시 | 사용자 확인 |
| 보증보험 가입 가능 여부를 확인했는가 | — | 확인함 / 못함 / 해당 없음 |

- 특약 키워드 후보는 `lib/rules.ts`의 결정론 문자열 매칭이다. "있음/없음"을 판정하지 않고 **"이 문구가 특약에 보입니다 / 보이지 않습니다 — 확인하세요"**로만 표시한다.
- 계약금 비율(5~10%)·잔금 금액의 적정성은 계산하지도 표시하지도 않는다 (R8).
- 보증보험 항목은 거래 유형별 적용 여부가 미확인이라 조건 분기 없이 "해당 없음" 선택지를 둔다 (V2-STATUS §6).
- 특약 **문구 예시**는 용어 설명(28건 체계)에 넣되 "예시이며 법률 자문이 아님" 면책을 붙인다. 특약을 대신 써 주는 기능은 만들지 않는다.
