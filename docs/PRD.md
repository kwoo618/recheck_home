## 1. 서비스 정의와 원칙

**한 줄**: 직방·다방·중개사에서 찾아온 매물을 계약 전에 2차 검증하도록 돕는 웹 서비스.

### 1.1 역할 분담 (전 기능 공통)
| 담당 | 역할 |
|---|---|
| 규칙(결정론) | 확인 항목 선정 · 안전 점검 · 거리 계산 · 금융 계산 · 집계 · 상태 전이 |
| AI (Gemini) | ① 붙여넣은 매물 텍스트 → 구조화 ② 우려사항 → 질문 변환 ③ 조사 기록 차이 요약 — **이 셋이 전부다** |
| 사용자 | 정보 확인·수정, 현장 조사, 답변 기록, 비교, **최종 선택·계약 판단** |

> **④ "(선택) 금융 트레이드오프 서술"은 2026-08-12에 삭제했다.** 근거: **CLAUDE.md R3** — AI는 위 3지점에만 쓴다.
> 금융은 `lib/finance.ts`의 순수 함수가 숫자만 내고, 가정·면책은 고정 문구(`FINANCE_ASSUMPTIONS`·`FINANCE_DISCLAIMER`)로 노출한다.
> "트레이드오프 서술"은 AI가 유리/불리를 말하게 되는 자리라 R1과도 부딪힌다.
> **AI를 4번째 지점에 추가하려면 R3 절차대로 근거를 제시하고 사용자 승인을 먼저 받아야 한다.**

### 1.2 핵심 원칙
1. AI는 판정하지 않는다 — "안전/위험/추천/유리" 결론형 표현 금지 (프롬프트 가드레일 + 출력 필터 이중 장치)
2. 판정 가능한 것은 전부 규칙으로 처리한다
3. AI는 "자유 텍스트 이해"가 꼭 필요한 지점에만 투입한다
4. 모든 섹션에 출처 배지(규칙 기반 / AI / 직접 입력)를 표시한다
5. 기록은 사용자의 것 — 현장 답변은 사용자가 직접 입력한다
6. **지도는 정보 제공까지만** — 거리·위치는 보여주되 입지 평가·동네 점수 시각화는 금지
7. **어떤 외부 의존성이 죽어도 핵심 검증 흐름은 동작한다** (지도·AI·좌표 각각 폴백 보유)

### 1.3 지도의 경계 — "탐색 지도"가 아니라 "내 매물 지도"
| 구분 | 기존 매물 앱 지도 | 리:체크 지도 |
|---|---|---|
| 목적 | 미지의 매물 탐색 | 내가 등록한 매물의 위치 파악·비교 |
| 데이터 | 서비스 보유 매물 DB | 사용자가 직접 등록한 매물만 |
| 지도 이동 | 신규 매물 로딩 | 아무것도 나타나지 않음 |
| 핀 클릭 | 매물 상세·중개사 연결 | 내 검증 진행 상황으로 이동 |

> 발표 문장: **"우리 지도에는 우리가 추천하는 매물이 없습니다. 사용자가 직접 가져온 매물만 있습니다."**

핀 색상은 **검증 상태로만** 구분한다. 가격 높낮이를 색으로 암시하는 것은 판정에 해당하므로 금지. 색상만으로 구분하지 않고 텍스트 라벨을 병기한다.

| status | 라벨 | 색 |
|---|---|---|
| `prep` | 검토중 | 회색 `#5A5E66` |
| `ready` | 방문대기 | 파랑 `#2C5FA8` |
| `recorded` | 기록완료 | 노랑 `#B7791F` |
| `confirmed` | 확정 | 초록 `#145C54` |
| `excluded` | 제외 | 빨강 `#B23A3A` |

> 단일 소스는 `components/map/status-pin.ts`의 `STATUS_PIN`이다. **5개 status 전부에 핀 스타일이 있다** — 문서에 4개만 적혀 `excluded`가 빠져 있던 것을 2026-08-12에 맞췄다.

## 2. 사용자 흐름 (3국면 — 실제 시간 구조 반영)

```
[국면 A. 방문 준비]  ─ 집 보러 가기 전
  매물 등록 (주소 검색 → 좌표·거리 자동 / 붙여넣기 AI 파싱 / 수기)
   → 정보 확인·수정 (사람 2차 확인)
   → 조사지 만들기
       · 직접 확인할 것 (규칙 자동 선정, 편집 가능)
       · 물어볼 것 (질문 은행 선택 + 기타 AI 변환 + "걱정 없음")
   → 조사지 인쇄 / PDF
            ↓  (며칠 뒤 현장 방문)
[국면 B. 방문 기록]  ─ 다녀온 직후
  결과 입력 (4택 퀵 입력 + 답변 기록 + "못 들음")
   → [활성 매물 2개↑] 비교
       · 위치 (다중 핀 지도 + 거리 표)
       · 기본 스펙 (▲▼ 정량 비교)
       · 금융·현금흐름 (실질 월 부담 계산) + 전환·협상 계산기
       · 질문-답변 상세 + AI 차이 요약
   → 사용자 선택 / 제외
            ↓
[국면 C. 계약]
  계약 전 안전 점검 (서류·권리, 필수/추천 구분)
   → 최종 점검표 인쇄 / PDF
   → 계약 확정 (명시적 결정)
   → 계약 당일 체크리스트 → 계약 후 / 입주 당일 / 입주 후
```

**시점 원칙(중요)**: 현장 항목(수압·곰팡이·소음)은 **방문 전에 체크하지 않는다.** 국면 A에서는 "확인할 목록"만 만들고, 실제 체크는 국면 B에서 한다. 계약 서류·권리 항목은 매물을 고른 뒤인 국면 C에 모은다.

## 3. 상태 모델 (단일화 — 서버 강제)

```
prep       정보 확인 필요 (등록 직후)
ready      방문 대기 (조사지 완성)
recorded   기록 완료 (방문 결과 입력)
confirmed  계약 확정
excluded   제외 (비교에서 탈락)

prep ─정보확인+조사지완성→ ready ─기록저장→ recorded ─확정→ confirmed
recorded/ready ─제외→ excluded ─복구→ prep      confirmed ─확정취소→ recorded
허용 외 전이는 canTransition() 검증 실패로 {ok:false} 반환 (서버에서 강제)

progress = (결과 입력된 visitChecks + 답변된 questions) / 전체 × 100
활성 매물 = status ∉ {confirmed, excluded}   ← 비교 대상
```
지도 핀 색상은 이 status에 1:1 대응한다.

## 4. 위치 기능 설계 (신규)

### 4.1 좌표 획득 흐름
```
[주소 검색 버튼] → 카카오(다음) 우편번호 서비스 임베드(무료)
   → 선택된 도로명/지번 주소
   → Geocoding(주소 → 위경도)
   → DB 저장: address, address_detail, latitude, longitude, distance_from_school
   → 실패 시: 좌표 null로 저장 → 홈에서 "위치 미지정" 그룹으로 분류
```
- **좌표 획득 실패가 서비스 흐름을 막지 않는다.** 지도에 못 찍혀도 검증·비교·인쇄는 전부 정상 동작.
- 상세주소(동/호수)는 **저장하되 지도·PDF·공유 화면에 노출하지 않는다** (개인정보·매물 특정 방지).

### 4.2 거리 표기
- 대구대학교 **경산캠퍼스 대표 좌표**를 상수로 고정(`lib/geo.ts` `SCHOOL_ORIGIN`), **Haversine 직선거리** 계산 후 등록 시 캐시(`distance_from_school`)
  - 출처: 카카오 로컬 API 조회, 2026-08-11. **캠퍼스 중심(POI)이며 정문 좌표가 아니다.**
  - 화면 표기는 **"대구대학교"**. "정문"이라 쓰지 않는다 (기준이 아닌 지점을 기준이라 표기하면 사실과 달라짐)
- 표기: `대구대학교에서 직선 820m` / 도보 환산 시 `도보 약 12분 (직선거리 기준 추정)` — **추정임을 반드시 병기**
- 실경로 기반 도보 시간(길찾기 API)은 로드맵

### 4.3 지도 구현 방침
- 카카오맵 JS SDK는 클라이언트 전용 → `next/dynamic` + `ssr:false`, 로딩 중 스켈레톤 노출
- 언마운트 시 지도 인스턴스 정리(메모리 누수 방지)
- 좌표·거리는 서버에서 계산해 내려주고 클라이언트는 렌더만 담당
- 키는 도메인 제한 클라이언트 키, `NEXT_PUBLIC_KAKAO_MAP_KEY`로 주입. **로컬(localhost) + Vercel 도메인 둘 다 등록**
- **지도 로딩 실패 시**: 지도 영역을 리스트로 대체하고 "지도를 불러오지 못했습니다" 안내. 검증 기능은 계속 동작
- 탐색 UI(지도 내 검색·필터) 미제공 + 지도 하단 고정 문구 "등록한 매물만 표시됩니다"

> **확인 결과 (2026-08-12 기준 · 단일 소스는 `docs/INFRA.md` §1·§3)**
>
> | 항목 | 상태 |
> |---|---|
> | 지도 SDK 무료 한도 | ✅ **1일 300,000회** (2026-08-11 확인) |
> | 도메인 등록 절차 | ✅ 앱 `1540296`에 `http://localhost:3000` + 배포 도메인 등록. 미등록 도메인은 `401 domain mismatched!`로 거부되는 것까지 실호출로 확인 |
> | 우편번호 서비스 사용 **방법** | ✅ 키·도메인 등록 없이 공식 CDN 스크립트 임베드 |
> | 로컬 API(주소→좌표) 일일 한도 | ⛔ **미확인** — 지도 SDK 300,000회는 **로컬 API에 적용되지 않는다** |
> | 우편번호 서비스 사용 **조건·한도** | ⛔ **미확인** |
> | 상업적 이용 조건 | ⛔ **미확인** |
>
> ⛔ 항목은 추측하지 않고 미확인으로 둔다. **이 값에 의존하는 제한 로직·안내 문구를 넣지 않는다** (R8).
> 한도에 닿아도 과금이 아니라 호출 차단이고, R4 폴백(지도 실패 → 리스트 / 좌표 실패 → `null`)이 있어 핵심 흐름은 동작한다.

## 5. 기능 명세

### 5.1 매물 등록 (탭 2개)
1. **주소 검색 + 수기 입력** (기본) — 별칭, **주소(검색)**, 상세주소(선택), 거래유형(전세/월세/매매/**사글세**), 보증금/월세, **선납 개월·총액(사글세)**, 면적, 관리비, 연식, 난방방식, 층수, 참고 링크(선택). 주소 선택 시 지도 미리보기에 핀 + 거리 표시
2. **텍스트 붙여넣기** — 매물 상세 텍스트를 붙여넣으면 Gemini가 구조화(약관 위반 없음: 사용자가 직접 복사한 자기 열람 정보). 실패 시 수기 탭 자동 전환

> **"링크" 탭은 2026-08-12에 문서에서 삭제했다** (구현에는 처음부터 없다).
> 링크로 매물 정보를 가져오는 것은 크롤링이라 **약관 위반이자 MVP Won't 범위**이고, "데모 더미 매칭"은 발표에서만 동작하는 장치였다.
> **참고 링크는 탭이 아니라 등록 폼의 입력 필드로 남아 있다** — 사용자가 나중에 원문을 다시 열어보기 위한 용도이고, 서비스가 그 링크를 읽지는 않는다.

### 5.2 정보 확인·수정 (사람 2차 확인)
자동 취득 정보는 틀릴 수 있으므로 전 필드 편집 가능한 확인 화면을 반드시 경유. 조건(연식·난방·층수) 변경 시 조사지 항목 재생성.

### 5.3 조사지 만들기
- **직접 확인할 것**: 조건-규칙 매핑으로 자동 선정(현장/설비/상세/가격 카테고리). 항목 제거·직접 추가 가능
- **물어볼 것**: 카테고리별 질문 은행(난방·냉방/수도·수압/소음·이웃/보안/관리비·비용/계약 조건/주변 환경) 체크 선택 + "목록에 없는 고민"만 AI 변환 + "따로 걱정 없어요" 옵션
  - 첫 자취생은 무엇을 걱정해야 할지 모른다 → 빈 입력창이 아니라 **선택형 목록**이 기본
- 질문 목록 수정·삭제 가능

> **2026-08-12 정정 — `관리비 포함 항목 현장 재확인`의 조건을 사글세까지 넓혔다.**
> 조건이 `dealType === '월세'`라 **사글세 매물의 조사지에는 이 항목이 없었다.** 사글세도 매달 관리비가 나간다.
> 계약서 측면(선납액에 관리비가 포함인지)은 안전 점검이 덮지만 **현장에서 눈으로 확인하는 항목이 비어 있었다.**
> 조건은 `'월세' || '사글세'` **명시 열거**로 뒀다 — `!== '전세'` 같은 부정형으로 쓰면 나중에 거래유형이 늘 때 아무도 검토하지 않은 채 자동으로 포함된다. 항목 선정은 사람이 검토하고 넣어야 한다.

### 5.4 조사지 인쇄 / PDF
매물 헤더(주소·거리 포함) + 직접 확인 표(항목 | 좋음 | 보통 | 문제 | 메모 빈칸) + 질문 표(질문 | 답변 빈칸) + 면책 문구. 인쇄 전용 스타일시트 + 브라우저 Print to PDF. 지도 이미지는 MVP에서 PDF에 넣지 않고 주소·거리 텍스트로 대체.

### 5.5 방문 기록

### 5.6 매물 비교 (활성 매물 2개 이상)
**① 위치** — 활성 매물 다중 핀 지도(fitBounds) + 표(동 단위 주소 / 대구대학교 직선거리 / 도보 추정). 위치 미지정 매물은 하단 별도 안내
**② 기본 스펙** — 숫자 행에 최고 ▲(빨강)·최저 ▼(파랑) + 범례 "수치 표시일 뿐 우열 아님". '문제있음' 건수, 미확인 건수 행 포함
**③ 금융·현금흐름** — §6 참조
**④ 질문-답변 상세** — 질문 합집합 기준, 미확인·못 들음 하이라이트. [차이점 AI 요약] 버튼(기록 없으면 비활성, 실패 시 표만)
**⑤ 선택** — 매물별 [이 매물로 진행] / [제외]

| 재계약 시 금액 인상 조건 (사글세) | 추천 | 미래 조건이고 현재 회수와 무관 |

> **2026-08-12 정정 — `근저당·압류·가압류 확인`의 선정 조건을 제거했다.**
> 구현에 `dealType !== '월세' || deposit >= 1000` 조건이 붙어 있어 **보증금 1,000만원 미만 월세에서는 이 항목이 목록에 나오지 않았다.** 스크린샷 러너가 찍은 인쇄본(보증금 500만 월세)에서 발견했다.
> 1,000만원은 어디서 온 값이 아니라 **우리가 정한 기준**이고, "이 금액 아래면 확인하지 않아도 된다"는 판정이다 (R1·R8). 이 표에도 조건 없는 필수로 적혀 있다.
> 보증금 500만도 대학생에게는 큰 돈이고, 선순위 근저당이 있으면 한 푼도 못 받을 수 있다는 사실은 금액과 무관하다. `tests/rules.test.ts`가 되돌아오는 것을 막는다.

> **사글세 5항목 추가 근거**: 선납금은 보증금이 아니라 **차임(월세) 선납**으로 취급되는 경우가 많아, 전입신고·확정일자를 해도 보증금처럼 보호받지 못할 수 있다. 위 항목들은 그 간극을 **계약서에서** 메우게 한다.
> 필수/추천은 기존 기준 그대로다 — 필수는 보증금·권리 상실로 직결되는 것, 추천은 금액 예측이나 미래 조건에 관한 것.

### 5.9 사글세 (2026-08-12 추가)

대구대 인근 자취방 상당수가 사글세다. 이 유형이 없으면 **타깃 사용자가 매물을 등록조차 못 한다.**

**등록** — 거래유형에 `사글세`를 추가하고 **선납 개월 수 · 선납 총액(만원)** 두 칸을 받는다.
두 칸 모두 nullable이다. **0("선납 없음")과 빈 값("아직 입력하지 않음")은 다르다** — 없는 값을 0으로 접으면 화면이 "월 0만원"이라는, 사용자가 넣지 않은 숫자를 만들어낸다.

**계산** (`lib/finance.ts` `calcPrepaid`)
```
월 환산액    = 선납총액 ÷ 선납개월
처음 드는 돈 = 보증금 + 선납총액
```
둘 다 사용자 입력값의 나눗셈·덧셈이다. **재계약 가정·중개보수 추정·공과금 추정을 넣지 않는다.**
입력이 없으면 계산하지 않고 `{ok:false, reason}`을 돌려준다(전환 계산기와 같은 규약).

**검증** — 안전 점검에 사글세 전용 5항목이 붙는다(§5.7). 조사지의 `관리비 포함 항목 현장 재확인`도 사글세에 포함된다.

> **비교 환산은 지원하지 않는다 (v2로 미룸).**
> 사글세와 전세·월세를 같은 잣대에 놓으려면 **기준 기간**을 정해야 하는데, 그 순간 서비스가 가정을 만든다 —
> 6개월 계약을 1년 기준으로 펴는 것은 "재계약을 1회 한다"고 가정한 것이고, 재계약 인상률·중개보수 재발생도 우리가 아는 값이 아니다.
> 화면에 뜬 숫자를 사용자는 "이 서비스가 알려준 기준"으로 받아들인다 (R1·R8).
> **유형이 섞이면 환산하지 않고 절대값만 둔다.** 사글세끼리는 월 환산액과 처음 드는 돈으로 비교할 수 있다.
> v2 조건은 `docs/ROADMAP-V2.md`에 있다 — 사용자가 기준 기간을 직접 입력하고 그 입력이 화면에 보일 때만 가능하다(전월세전환율이 선례다).

### 5.10 홈 랜딩 (2026-08-12 추가)

매물이 **0건일 때만** 보이는 첫 화면. 서비스가 무엇을 하는지와 3국면 흐름을 설명한다.
매물이 하나라도 있으면 지도·리스트 하이브리드 홈(§7.1)으로 대체된다.

> 시연에서 랜딩을 보여주려면 **시크릿 창**으로 열어야 한다. 기존 세션에서 매물을 지우면 되돌릴 수 없다.

### 5.11 세션 재시작 (2026-08-12 추가)

홈에서 **새 익명 세션을 시작**한다. `rc_session` 쿠키를 새 UUID로 재발급하는 것이 전부다.

> **데이터를 지우지 않는다.** 기존 매물·조사지·질문·기록은 DB에 그대로 남고 **접근 경로만 끊긴다.**
> 그래서 "초기화"도 "삭제"도 아니다 — 액션 이름이 `startNewSession`인 이유이고, 화면 문구도 "새로 시작"이어야 한다.
> "초기화"라고 쓰면 사용자는 데이터가 지워졌다고 이해하는데 사실이 아니고, 반대로 "지워졌겠지" 하고 안심하는 것도 사실이 아니다. 둘 다 틀린 안내다.
> **되돌릴 수 없다** — 이전 쿠키 값을 어디에도 남기지 않으므로 옛 세션의 매물에는 다시 접근할 방법이 없다. 화면이 확인 단계를 두는 이유다.

### 5.12 용어 설명 (2026-08-12 추가)

전세가율·확정일자·대항력·근저당처럼 **첫 자취생이 모르는 용어 28건**에 화면 내 설명을 붙였다.
팀원 테스트에서 "무슨 말인지 모르겠는 문구"가 가장 많이 나온 지점이고, 심사위원이 멈추는 곳도 같다.

> 설명을 늘리는 것은 되지만 **판정·숫자 기준을 넣으면 R1·R8 위반이다.** "얼마부터 위험" 같은 문장을 넣지 않는다.

### 5.13 `/admin` 집계 대시보드 (2026-08-12 추가 · 발표용)

운영 지표와 **R1·R2·R4가 실제로 작동한다는 증거**를 한 화면에 모은다. 9개 섹션(요약·퍼널·상태·지역·금액·좌표 성공률·AI 폴백률·규칙 vs AI·질문 은행).

> ⚠ **발표용 임시 인증이다. 실제 인증이 아니다.**
> `?key=` 쿼리스트링과 `ADMIN_TOKEN` 환경변수를 문자열 비교하는 것이 전부다.
> URL이 브라우저 히스토리·서버 로그·Referer에 남고, 링크를 받은 사람은 누구나 들어온다.
> **발표 슬라이드에 URL을 넣지 않는다.** 발표 후 `ADMIN_TOKEN`을 지우면 `notFound()`로 막힌다(토큰 미설정 = 페이지 없음이 기본값).
> **로그인 도입 시 교체 대상이다.**

개인정보는 **읽지 않는다** — 상세주소·별칭·메모·답변 원문·방문 기록을 select 자체를 하지 않는다. 화면에서 빼는 것만으로는 부족하다(RSC 페이로드에 남는다). 주소는 읍·면·동까지만 집계에 쓴다.

**"매칭 수"를 넣지 않는다.** 이 서비스는 매물을 매칭하지 않는다 — 그 숫자가 뜨는 순간 직방·다방과의 차이가 무너진다.
**질문 은행은 읽기 전용이다.** 문장이 DB 매칭 키라 고치면 이미 답한 기록이 고아가 된다.
**시연용 데이터를 실사용과 섞어 한 숫자로 보여주지 않는다** — 상단에 `실사용 N건 · 시연용 M건`을 항상 노출하고, 퍼널은 실사용만으로 계산한다. 판정하지 않는 서비스가 자기 지표도 부풀리지 않는다.

## 6. 금융·현금흐름 비교 명세

### 6.1 계산 규칙 (순수 함수 — 유닛 테스트 대상)
```
입력: 매물 {dealType, price, deposit, mgmtFee}, 금융 프로필 {cash, loanCap, rate}
필요보증금 need   = 월세면 deposit, 전세면 price      (매매는 v1 계산 제외 — 상환 구조 상이)
예상대출  loan    = min( max(0, need − cash), loanCap )
초기자기자금 upfront = need − loan                     (upfront > cash → "부족" 사실 표시)
월이자   mInt     = loan × (rate/100) ÷ 12            (이자만 상환 가정 — 화면 명시)
월주거비 monthly  = 월세 + 관리비 + mInt               (중개보수·이사비 미포함 — 화면 명시)
```

### 6.2 보증금↔월세 전환 (참고 계산)
```
추가보증금 = (현재월세 − 목표월세) × 12 ÷ (전환율/100)
```
**전환율(`cvRate`)에 기본값을 넣지 않는다 — 사용자가 직접 입력한 값으로만 계산한다.** 입력 전에는 계산 결과 대신 안내 문구만 띄운다.

> 2026-08-12 정정. 원문은 "법정 전월세전환율 수준을 참고로 제시하되 수정 가능"이었으나 **2026-08-11 결정으로 기본값을 넣지 않기로 했고 구현도 그렇다.**
> 이유: 법정 전환율은 기준금리 연동이라 시점에 따라 변하고, **화면에 미리 떠 있는 숫자를 사용자는 "이 서비스가 알려준 기준"으로 받아들인다.** 기본값을 제공하는 것 자체가 판정에 해당한다 (R1·R8).
> 금칙어 필터는 문장을 거르지만 숫자는 아무도 거르지 않는다 — 새 입력 필드에 기본값을 넣기 전에 "이 숫자를 서비스가 정해도 되는가"를 먼저 물을 것.

**"법정 전환율은 갱신 계약의 상한 기준이며 신규 계약 협상에 강제력 없음"** 라벨 고정 노출(`CONVERSION_NOTICE`).

### 6.3 협상 질문 생성 — 결정론 템플릿 (AI 아님)
```
"보증금을 {신규보증금}만원 수준으로 올리는 대신 월세를 {목표월세}만원으로 조정할 수 있을까요?"
```
숫자가 이미 계산돼 있으므로 AI 불필요. [질문 목록에 추가] 버튼으로 해당 매물 질문에 편입.

### 6.4 가드레일
- 금칙어: 추천 / 안전합니다 / 위험합니다 / 유리합니다 / 불리합니다 / 더 낫 / 가장 좋 …
- 면책 상시 노출: **"본 계산은 참고용이며 금융상품 권유·투자자문이 아닙니다. 실제 대출 한도·금리·조건은 금융기관에서 확인하세요."**
- "⚠부족"은 산술적 사실(자기자금 > 보유현금) 표시일 뿐 판정이 아님 — 코드 주석·문서에 명시

#### 입력 상한 — DB에 닿기 전에 서버에서 거른다 (2026-08-12 문서화)

상한을 넘는 값이 INSERT까지 가면 Postgres가 예외를 던지고, 그러면 Server Action이 `ActionResult` 대신 **예외를 밖으로 내보내** 프론트가 에러 바운더리(흰 화면)를 만난다. `lib/actions/properties.ts`의 `checkLimits()`가 INSERT/UPDATE 전에 거른다.

| 필드 | 타입 | 상한 |
|---|---|---|
| `price` · `deposit` · `mgmt_fee` · `age` | `int4` | 2,147,483,647 |
| `area` | `numeric(6,2)` | 9999.99 |
| `name` | `text` | 60자 (DB 제한 아님 — 화면이 감당 못 함) |
| `floor` | `text` | 6자 (동일) |

**음수는 상한과 다르게 다룬다** — `toInt`가 0으로 보정한다. "-5를 입력했더니 저장이 안 된다"보다 "0으로 들어갔다"가 덜 막힌다.
**새 숫자 필드를 추가하면 반드시 `checkLimits()`에 넣을 것.**

### 8.4 API 계약 (프론트↔백 — 먼저 확정, 이후 변경 금지)
```ts
type Property = {
  id, name, address, addressDetail, latitude|null, longitude|null,
  distanceFromSchool|null, dealType:'전세'|'월세'|'매매'|'사글세',
  prepaidMonths|null, prepaidTotal|null,        // 사글세 전용. 0과 null은 다르다
  price, deposit, mgmtFee, area, age,
  heating:'개별난방'|'중앙난방'|'지역난방'|'모름', floor, link,
  status:'prep'|'ready'|'recorded'|'confirmed'|'excluded',
  noConcern, progress,
  visitChecks: VisitCheck[], questions: Question[],
  safetyChecks, contractChecks, afterChecks
}
```
**목록 갱신일: 2026-08-12 (2차)** — 1차에서 누락 3개(`getProperty` · `listActiveProperties` · `addQuestion`)를 채우고 `/api/geocode` 응답 형태를 실제와 맞췄다. 2차에서 `startNewSession`을 추가했다.
이 표는 "이후 변경 금지" 계약이므로 **변경·추가할 때마다 이 날짜를 갱신할 것.** 날짜가 없으면 목록이 최신인지 아무도 모른다.

| 구분 | 함수/경로 | 비고 |
|---|---|---|
| Server Action | listProperties / createProperty / updateProperty / deleteProperty | createProperty 시 좌표·거리·조사지 항목 자동 생성 |
| Server Action | **getProperty(id)** | 단건 조회. 남의 매물은 `null` — "권한 없음"이 아니라 "없는 것"으로 다룬다 |
| Server Action | **listActiveProperties()** | 비교 대상 = status ∉ {confirmed, excluded} |
| Server Action | setStatus(id, status) | `canTransition()` 검증, 위반 시 `{ok:false}` |
| Server Action | addVisitCheck / removeVisitCheck / saveVisitResults | |
| Server Action | toggleBankQuestion / **addQuestion** / editQuestion / removeQuestion / saveAnswers | `toggleBankQuestion`은 **질문 문구 문자열을 매칭 키로** 쓴다 — `QUESTION_BANK` 문장을 고치면 기존 질문이 고아가 된다 |
| Server Action | toggleCheck(id, group, ruleId, on) | safety / contract / after |
| Server Action | getFinance / saveFinance | 사용자당 1개. `cvRate`는 기본값 없이 사용자 입력만 저장 |
| Server Action | **startNewSession()** → `ActionResult<void>` | 세션 쿠키를 새 UUID로 재발급. **데이터를 지우지 않는다**(§5.11). `redirect()`를 부르지 않고 화면이 `router.refresh()`로 갱신한다 |
| Route | POST /api/geocode `{address}` → `{ok:true, lat, lng}` \| `{ok:false, lat:null, lng:null, reason}` | 실패해도 200 |
| Route | POST /api/ai/parse `{text}` → `{ok:true, data}` \| `{ok:false, reason}` | 실패 시 ok:false |
| Route | POST /api/ai/questions `{concern}` → `{ok, questions[], source:'ai'\|'template', reason?}` | 실패해도 questions는 채워 보낸다(템플릿). `source`가 화면 출처 배지 값 |
| Route | POST /api/ai/summary `{propertyIds[]}` → `{ok:true, summary}` \| `{ok:false, reason}` | 실패 시 표만 |
| Util | `lib/finance.ts` / `lib/geo.ts` | 순수 함수, 유닛 테스트 |

> **Server Action은 예외를 던지지 않고 `ActionResult{ok,error}`를 돌려준다.** 비전공 프론트가 `try/catch` 없이 `ok`만 분기하게 하려는 것이라, 액션 안에서 예외가 새면 이 계약이 깨진다.
> 그래서 입력 상한은 DB에 닿기 전에 `checkLimits()`가 거른다(§8.3).

**AI·geocode 라우트는 실패해도 HTTP 200 + `ok:false`** — 프론트가 에러 처리 없이 폴백 UI만 그리면 되게 한다(비전공 프론트 팀 배려).

## 9. MVP 범위 (MoSCoW)

**Must**: 주소 검색+수기 등록 / 정보 확인·수정 / 조사지(규칙+질문은행) / 조사지 인쇄 / 방문 기록 / 비교(위치·스펙·상세) / 안전 점검 / 계약 확정 / 계약 후 절차 / 상태 전이 / 홈 지도·리스트 하이브리드
**Should**: 붙여넣기 AI 파싱 / 우려→질문 AI 변환 / 금융 비교 + 전환·협상 계산(결정론이라 리스크 낮음) / 최종 점검표 PDF
**Could**: 비교 AI 차이 요약 / 확정 취소·제외 복구 / 카드↔핀 양방향 연동 / AILog 뷰어
**Won't(로드맵)**: 로그인, 사진 첨부, 공유 링크, 핀 클러스터링·필터, 수동 핀 조정, 실경로 도보시간, 링크 크롤링, 등기부 OCR, 리뷰(UGC), 초기 비용 계산기, 특약 라이브러리

| 메모에 민감정보 입력 | 입력란 안내 문구 + PDF 공유 유의 문구 |

> **2026-08-12 정정 — Gemini 행**: 원문은 "동일 입력 캐싱 + 8초 타임아웃"이었다.
> - **타임아웃은 12초**(`lib/ai/models.ts`의 `GEMINI_TIMEOUT_MS`). 실측이 parse 6.1초 / summary 5.9초 / questions 4.8초라 8초는 여유가 1.9초뿐이었다. 폴백이 있으므로 늘려도 최악은 템플릿 질문이다.
> - **동일 입력 캐싱은 구현하지 않았다.** 매물 텍스트·우려 문장은 사용자마다 달라 캐시 적중을 기대할 자리가 아니었고, 대신 **모델 체인**(기본 모델 실패 시 폴백 모델)과 템플릿 폴백으로 대응한다.
> - Gemini 무료 티어 RPM/RPD는 **미확인**이다. 이 값에 의존하는 제한 로직을 넣지 않는다 (R8).
