# 발표 자료용 화면 사진 — 팀원 안내

> 슬라이드에 넣을 화면 사진을 어디서 받고, 어느 사진을 어디에 쓰는지 정리한 문서입니다.
> 개발을 몰라도 읽을 수 있게 썼습니다. 2026-08-12 기준.

---

## 1. 사진이 왜 저장소에 없나요

**일부러 뺐습니다.**

사진은 화면을 고칠 때마다 다시 찍어야 합니다. 저장소에 넣어두면 화면은 바뀌었는데 사진은 옛날
것이 남아, 슬라이드에 **지금은 없는 화면**이 들어갈 수 있습니다. 발표장에서 "이 화면 지금 없는데요"가
가장 나쁩니다.

그래서 사진은 **필요할 때 새로 만들어 쓰는 것**으로 정했습니다. 파일 용량도 커서 저장소가 무거워지는
문제도 함께 피했습니다.

---

## 2. 사진 받는 방법

### 방법 A — 강우에게 요청 (가장 빠름)

강우에게 "발표용 사진 주세요"라고 하면 압축 파일로 보내드립니다.
**필요한 사진 이름을 함께 적어주시면 그것만 골라 드립니다** (아래 4번 표 참고).

### 방법 B — 직접 만들기

개발 환경이 설치된 컴퓨터에서 아래 네 줄을 **순서대로** 입력합니다.
검은 명령창(터미널)에 한 줄씩 붙여넣고 엔터를 치면 됩니다.

```
npm run qa:seed
npx next build
node --env-file=.env.local node_modules/next/dist/bin/next start -p 3000
npm run qa:shoot
```

- 세 번째 줄은 **창을 닫지 말고 그대로 두세요.** 그 창이 앱을 켜두는 역할입니다.
- 네 번째 줄은 **새 창을 하나 더 열어서** 입력합니다.
- 전부 끝나는 데 2분 30초쯤 걸립니다.

끝나면 사진이 이 폴더들에 생깁니다.

| 폴더 | 무엇 |
|---|---|
| `docs/qa/shots/390/` | **폰 화면 크기** — 발표에는 주로 이걸 씁니다 |
| `docs/qa/shots/1440/` | 노트북 화면 크기 |
| `docs/qa/pdf/` | 인쇄물 (PDF와 미리보기 그림) |

> ⚠ **`-p 3000` 부분을 바꾸지 마세요.** 지도가 이 번호에서만 제대로 나옵니다.
> 다른 번호로 켜면 지도 자리에 목록만 나와서, 사진만 보면 지도가 고장 난 것처럼 보입니다.

> ⚠ 세 번째 줄에서 **"이미 사용 중"** 같은 말이 나오면, 앱이 이미 켜져 있는 것입니다.
> 그 창을 닫고 처음부터 다시 하세요.

### 랜딩 화면은 위 방법으로 안 나옵니다

첫 화면(서비스 소개)은 **매물이 하나도 없을 때만** 보입니다. 위 방법은 연습용 매물 5개를 미리
넣어두기 때문에 그 화면 대신 매물 목록이 찍힙니다.

랜딩 사진 4장은 강우가 따로 찍어 `docs/qa/shots/landing/` 에 넣어뒀습니다. **강우에게 요청하세요.**

## 4. 슬라이드에 넣을 때 — 어디를 잘라내나

사진이 세로로 아주 깁니다. **통째로 넣으면 글씨가 안 보입니다.** 아래를 참고해 잘라 쓰세요.

| 파일 | 잘라낼 부분 |
|---|---|
| `08-safety-monthly.png` | **위에서부터 "계약 전 안전 점검" 제목 ~ 항목 4개까지.** 아래쪽 노란 경고칸과 버튼은 잘라냅니다 |
| `07-compare.png` | 아주 깁니다. **"② 기본 스펙" 표 하나 + 그 아래 회색 설명 두 줄**만 남기세요 |
| `landing-1440-limits.png` | **자를 것 없이 그대로 넣으세요.** 검은 배경 블록만 잘라둔 사진이라 손댈 필요가 없습니다 |
| `landing-390-limits.png` | 위와 같은 내용의 **세로형**. 슬라이드가 세로로 길면 이쪽이 낫습니다 |
| `landing-390-full.png` | 두 가지로 씁니다. ① **맨 위 3칸짜리 띠**(찾기 → 확인 → 계약)만 잘라내면 "저희는 가운데 단계입니다"가 한 장으로 보입니다 ② 전체를 넣을 때는 흐름만 보여주는 용도로 — **글씨는 안 읽힙니다** |
| `01-home.png` | **지도와 그 바로 아래 회색 한 줄**까지. 위쪽 제목·버튼은 잘라냅니다 |
| `05-sheet-jeonse.png` | **맨 위 매물 이름 ~ 단계 표시(A·B·C) 줄까지만.** 잠긴 C와 안내 문구가 핵심입니다 |
| `09-contract-monthly.png` | **단계 표시 줄만.** 위 사진과 나란히 놓으면 순서가 드러납니다 |
| `06-record-monthly.png` | **항목 2~3개 분량.** 버튼 4개가 한 줄에 들어간 게 보이면 충분합니다 |
| `print-survey-sheet.png` | **표 윗부분.** 결과 칸이 비어 있는 게 보이는 데까지 |

> 자르기는 **윈도우 캡처 도구**(윈도우키 + Shift + S)나 파워포인트의 그림 자르기로 하면 됩니다.
> 원본 파일은 지우지 말고 복사본을 자르세요.

## 5. 사진을 다시 받아야 하는 때

- **화면 글씨가 바뀌었을 때** — 슬라이드와 실제 화면이 다르면 발표장에서 바로 지적당합니다
- **발표 직전 한 번** — 앱이 잠들어 있다가 처음 열면 느립니다. 미리 한 번 켜두는 것을 겸합니다

---

## 6. 화면 개수는 이렇게 씁니다

> **사용자 화면 8개 + 인쇄 레이아웃 2종 + 관리자 대시보드 1개**

- 짧게 써야 하면 **"화면 8개 + 인쇄 2종"** 으로 줄여도 됩니다.
- **관리자 화면은 슬라이드에서 빼도 됩니다.** 주소를 아는 사람은 누구나 들어올 수 있는 상태라
  **주소를 슬라이드에 적지 마세요.**
- 첫 화면(서비스 소개)은 홈 화면의 한 모습이라 **개수에 따로 세지 않습니다.** 다만 슬라이드에서는
  따로 보여줘도 됩니다.

자세한 근거는 `docs/SCREENS.md` 에 있습니다. 숫자가 헷갈리면 그 문서가 기준입니다.
