### ② 화면 수 표기
실제 파일은 **화면 8개 + 인쇄 레이아웃 2종 = 10개**.
"9개 화면"으로 세던 초기 기준과 다르다. 발표 자료에서 하나로 통일할 것.
권장 표기: "화면 8개, 인쇄 레이아웃 2종".

**어디를 고쳐야 하는지 (2026-08-12 확인):**
- `docs/PRD.md`에는 **화면 수 표기가 아예 없다** — 고칠 것이 없다.
  (§7 와이어프레임은 7절 7.1~7.7로 나뉘어 있을 뿐 화면 개수를 주장하지 않는다.
  홈이 데스크톱·모바일 2절로 갈리고 7.7이 안전 점검·계약 후를 함께 담고 있어 절 수 ≠ 화면 수)
- "화면 9개"는 **`docs/HANDOFF-FRONT.md` §"화면 9개 전부 포팅 완료"** 한 곳뿐이다.
  프론트 세션 문서이므로 **프론트 세션이 고칠 것.**
- `docs/PORTFOLIO-NOTES.md`·`docs/HANDOFF-BACK.md`는 이미 "8개 + 인쇄 2종"으로 맞다.

## 5. 알려진 한계 (고치지 않기로 한 것)

| 항목 | 이유 |
|---|---|
| 브라우저 뒤로가기로 이탈 시 방문 기록 유실 | App Router에 이동 가로채기 공개 API 없음. `history` 조작은 부작용이 큼 |
| 동시 요청 중복 3건 (등록·질문 토글·항목 추가) | 클라이언트 가드로 막음. 서버 차단은 스키마 변경이 필요해 보류 |
| 도보 최소거리 미지원 | 카카오 길찾기는 유료 API. 직선거리 + "직선거리 기준 추정" 병기가 R8의 표현 |
| 면적·관리비 빈 값이 0으로 저장 | nullable 스키마 변경 대신 표시로 우회. 관리비 0은 실제 값일 수 있어 그대로 표시 |
| 홈·비교 화면 `Ctrl+P` 시 화면 그대로 인쇄 | 인쇄 버튼이 없는 화면. MVP 범위 밖 |
| **`/admin` 인증이 실제 인증이 아님** | **발표용 임시 구현.** `?key=`와 `ADMIN_TOKEN`을 문자열 비교하는 것이 전부다. URL이 히스토리·로그·Referer에 남고, 링크를 받은 사람은 누구나 들어온다. **발표 슬라이드에 URL을 넣지 말 것.** 발표 후 Vercel에서 `ADMIN_TOKEN`을 지우면 `notFound()`로 막힌다. 로그인 도입 시 교체 필요 |
| 퍼널의 제외(excluded) 매물은 등록 단계까지만 집계 | 제외 시점의 진행 단계를 기록하지 않는다. 조사지를 완성한 뒤 제외된 건은 뒤 단계에서 빠져 전환율이 실제보다 낮게 나올 수 있다. 화면에 그렇게 적어 뒀다 |
