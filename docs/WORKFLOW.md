## 1. 구조

```
E:\project\
├─ recheck\          main 브랜치 · 백엔드 세션
│   └─ .git\         저장소 본체
└─ recheck-front\    feat/screens 브랜치 · 프론트 세션
    └─ .git          파일(포인터). 위 .git을 가리킴
```

`git worktree`로 같은 저장소를 두 폴더에 다른 브랜치로 체크아웃했다.
파일은 디스크상 별개지만 커밋 이력을 공유하므로, 한쪽이 커밋하면 다른 쪽에서
`git merge`로 바로 가져올 수 있다. clone 두 번과 달리 원격을 거치지 않는다.

### 재구성 방법

```powershell
cd E:\project\recheck
git status                                    # working tree clean 확인
git worktree add ..\recheck-front feat/screens
cd ..\recheck-front
npm install
copy ..\recheck\.env.local .env.local          # gitignore라 안 따라옴
code .
```

새 창에서 Claude Code **익스텐션**을 연다(CLI 아님 — 익스텐션은 열려 있는 폴더를
작업 디렉터리로 잡는다). 좌측 하단 브랜치가 `feat/screens`인지 확인할 것.

정리: `git worktree remove ..\recheck-front`

## 2. 담당 분리

| | 쓰기 허용 | 금지 |
|---|---|---|
| **백엔드** (`main`) | `app/`, `lib/`, `db/`, `drizzle/`, `fixtures/`, `components/map/`(로직) | `components/screens/` |
| **프론트** (`feat/screens`) | `components/screens/`, `components/map/`(스타일만) | `app/`, `lib/`, `db/`, 문서 |

디렉터리가 갈려 있어 **전 기간 병합 충돌 0건**이었다.

### 충돌이 0건이었던 이유 (운이 아니다)

1. **타입을 계약으로 사용** — 프론트가 백엔드 타입을 `import type`으로 직접 가져다 썼다. 콜백 20여 개가 처음 맞물렸을 때 불일치 0건.
2. **선택 prop으로 기능 인계** — 프론트가 `onDelete`·`onSetStatus`를 선택 prop으로 만들어, 백엔드가 연결하기 전까지 버튼이 렌더되지 않고 빌드도 깨지지 않았다.
3. **남의 디렉터리는 고치지 않고 목록으로 넘김** — 문제를 발견해도 직접 수정하지 않고 보고만 했다.

## 3. 진행 규칙

**한 세션에는 한 번에 하나의 지시만.** 응답 받고 → 확인하고 → 다음 지시.
병렬은 세션 **간**에만 적용한다. 진행 중인 세션에 다음 지시를 미리 쌓아두면,
그 사이 세션이 스스로 판단해 상황을 바꿔놓아 프롬프트의 전제가 틀어진다.

**보고 형식을 강제한다.**
```
"판단 필요"와 "완료 보고"를 분리해서 써주세요.
판단 필요 항목이 없으면 "판단 필요 없음"이라고 명시해주세요.
```
"판단 필요 없음"으로 끝나는 보고는 검토 없이 다음 지시로 넘어가도 된다.

**가벼운 작업은 묶어서 보낸다.**
```
아래 3개를 연속으로 진행하세요. 중간 승인 불필요합니다.
판단이 필요한 지점에서만 멈추고, 아니면 다 끝내고 한 번에 보고해주세요.
```

## 4. 검증의 한계 — 가장 중요한 항목

세션들은 **브라우저를 볼 수 없다.** 이 프로젝트에서 실제로 그 틈에서 새어나온 버그들:

| 버그 | `tsc`·`eslint`·HTTP 200 통과 여부 |
|---|---|
| 그리드 컬럼 뒤바뀜 → 한글이 음절 단위로 깨짐 | 전부 통과 |
| 붙여넣기 분기 ②가 도달 불가능한 죽은 코드 | 전부 통과 |
| 부분 성공을 실패로 처리해 6개 필드 폐기 | 전부 통과 |

**"확인했습니다"를 쓰기 전에 무엇을 확인했는지 구분할 것.**
코드 경로 확인 ≠ 런타임 확인. 이 프로젝트에서 프론트가 코드 경로만 보고 넘긴
버그를 백엔드가 실입력으로 두 번 잡았다.

**클라이언트 가드는 서버 테스트로 검증되지 않는다.** `useSingleFlight` 같은
중복 방지는 서버에서 액션을 직접 부르면 우회되므로, 서버 테스트 통과를 근거로
"중복 방지가 동작한다"고 보고해서는 안 된다.

### 사람이 반드시 봐야 하는 것
- 브라우저 콘솔 에러
- 지도 타일 실렌더
- 인쇄 미리보기 (`Ctrl+P`)
- 클릭 상호작용 — 더블클릭, 이탈 경고, 탭 전환, 폼 채움
- 모바일 390px 레이아웃
- 시각적 어긋남 (톤, 정렬, 여백)

## 6. 세션 재시작

### 종료 전
```
이 세션을 종료하고 새로 시작하려고 합니다.
docs/HANDOFF-[FRONT/BACK].md를 최신 상태로 갱신하고 커밋해주세요.
이 세션에서 새로 내린 판단 중 코드만 봐서는 알 수 없는 것을 추가해주세요.
```

### 시작할 때
```
리:체크 프로젝트 [프론트/백엔드] 세션을 이어받습니다.
CLAUDE.md → docs/HANDOFF-[FRONT/BACK].md → docs/INFRA.md 순으로 읽고,
git log --oneline -20으로 현재 상태를 파악해주세요.
```

### 이 Claude 프로젝트 채팅을 새로 시작할 때
프로젝트 지식에 `PROJECT-STATUS.md` · `CONSOLE-SETTINGS.md` · `WORKFLOW.md`와
저장소 최신 `INFRA.md` · `CLAUDE.md` · `PRD.md`를 올려둘 것.
채팅 기억은 이어지지 않으므로, 이 문서들이 유일한 연속성이다.

## 7. 재사용할 만한 프롬프트 패턴

**자가 점검 요청** — 실사용 관점으로 문제를 스스로 찾게 한다.
```
실제 사용자가 할 만한 행동을 다양하게 시도하며 문제를 찾아주세요.
코드 리뷰가 아니라 사용 시나리오 기준입니다.

- 긴 스크롤 끝에서 다음 행동을 찾기 어려운 곳
- 뒤로 갈 방법이 없는 곳 / 저장 여부를 알 수 없는 곳
- 빈 상태에서 화면이 어색한 곳
- 극단값: 아주 긴 이름, 0, 999, 빈 값
- 실수 복구: 잘못 등록·잘못 누름·잘못 확정
- 같은 버튼을 두 번 빠르게 눌렀을 때
- 모바일 390px에서 손가락이 닿기 어려운 곳

발견 목록을 우선순위(시연 차단 / 사용 불편 / 사소함)와 함께 주세요.
수정하지 말고 목록만 주세요.
```
이 한 번의 요청으로 21건이 나왔고 그중 4건이 시연 차단이었다.

**교차 검증** — 한쪽이 만든 것을 다른 쪽이 실입력으로 태운다.
```
프론트 수정이 끝났습니다. 병합하고 실입력으로 확인해주세요.
코드 경로가 아니라 실제 호출로 검증받겠습니다.
```
프론트의 "코드 경로만 확인" 한계를 백엔드가 메웠다.
